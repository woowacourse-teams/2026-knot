# 구간 전사 출시 검증

2026-10-18 기준 출시 판정은 **Hold**다. 구간 처리·결과 저장·정리 기능은 실제 S3와 native AI 연결에서 성공했지만, 정상 동시 녹음 두 개의 종료 후 30초 목표를 반복해서 충족하지 못했다. 제품 Chrome, 실제 회의의 검수된 화자 정답, 배포·canary·rollback 검증도 완료하지 않았다.

## 재현 도구와 범위

`tools/incremental-transcription/`의 opt-in 도구는 실제 S3, 격리 PostgreSQL, BE 서비스, 별도 localhost AI를 연결한다. 5초 조각을 실제 음성 시계에 맞춰 공급하고 마지막 부분 조각도 실제 frame 수에 맞춘다. 종료 전 대기열 소진을 기다리지 않는다.

종료 서비스 호출부터 최종 전사와 문서 접수까지 측정한다. 실제 제품 브라우저와 인증 HTTP 경로는 포함하지 않으며 문서 생성은 mock 접수만 확인한다. 정제 결과에 source commit, dirty 여부, AI JAR SHA-256, 공급 지연, 실패·정리 상태를 남긴다.

실행에는 #816·#817 구현을 포함한 소스가 필요하다. `--run` 없는 검사는 네트워크·프로세스·임시 파일·S3 쓰기를 시작하지 않는다. 원문·벡터·오디오·인증값은 공개 결과에 남기지 않고 새 UUID prefix만 정리한다.

## 병목 근거

공개 70초 실행에서 종료 시 이미 처리 중이던 40초 입력은 5.889초가 더 필요했다. 이후 40초 입력 9.639초, 15초 tail 두 개 5.082초·5.064초를 직렬 수행했다. 종료 후 잔여 native 처리 약 25.674초, 작업 사이 공백 약 2.240초, 마지막 결과 이후 채택·관측 약 0.25초였다.

파일 생성 시각을 관측한 근사치이며 공백에는 BE 저장·대기열·조립·S3·AI 다운로드가 섞여 있다. 공백을 전부 DB 비용으로 해석하지 않는다. 61초 실험의 최종 WAV는 종료 후 0.740/1.381초 안에 READY였으므로 이 짧은 입력에서는 native 처리와 대기가 주요 비용이다.

2시간 분량의 반복 PCM 두 개를 실제 S3에 저장한 뒤 종료한 별도 실험에서는 첫 녹음이 55.873초, 두 번째가 109.554초에 READY가 됐다. 각 녹음의 1,440개 객체를 직렬로 읽었고 WAV 조립은 각각 51.493초·49.320초였다. 두 번째 녹음은 단일 최종화 worker를 기다리는 데 55.838초가 추가됐다. 최종 PUT·HEAD는 각각 4.109초·4.318초였다.

각 WAV의 SHA-256, 230,400,044byte 길이, READY와 COMPLETED를 검증했고 실험 객체 version과 delete marker가 0개임을 두 번 확인했다. 이는 로컬 JVM에서 실제 S3까지의 1회 실측으로 native 전사는 제외했다. 운영 EC2 성능이나 2시간 자연 회의의 전사 품질을 대신하지 않는다. 다만 이 실행 환경에서는 tail 전사가 기다리는 READY 조건만으로 이미 30초를 초과했다.

## 통제된 화자 연결 회귀

서로 다른 한국어 합성 voice 두 개를 90초에 배치하고 0~35·25~65·55~90초의 실제 native 결과를 production BE merger에 전달했다. 최종 global label은 두 개였고, 하나의 고정 일대일 매핑으로 평가했을 때 포함된 음성 구간의 label은 모두 일치했다.

에너지 마스크로 잡은 43.45초 중 한 개 label이 덮은 비율은 94.223%였다. 30·60초 경계 ±1초는 모두 덮었지만 짧은 B 응답의 마스크 0.22초는 누락됐고 짧은 A 응답 0.57초는 52.63%만 덮었다. 이를 사람 화자 정확도나 DER로 해석하지 않는다. 검수된 실제 회의 품질 판정은 남아 있다.

실제 BE merger 테스트와 평가기 단위 6건을 통과했다. 실행 프로세스 종료를 확인한 후 비공개 음성·벡터·출력 47개 파일을 정리했고 정제된 지표와 재현 스크립트만 보존했다.

- Python 단위·프로세스 회귀 16건: 실행 opt-in, 입력 길이·명시적 반복, 정제, region별 S3 host 제한, 제한 시간·중단 시 소유 프로세스 그룹 종료, 외부 PID 보존, 별도 native 그룹의 정리 기록 확인.

공개 70초 실측 뒤 드라이버의 전체 실행·부팅 시간 제한과 BE·AI 소유 프로세스 그룹 정리를 강화했다. 별도 그룹으로 실행되는 native 작업은 `process-owner.json`의 CLEANED 상태도 확인한다. 종료나 정리 기록을 확인하지 못하면 실패로 보고하고 비공개 복구 파일을 보존한다. 이 추가 변경은 실제 자식·손자 프로세스와 순수 회귀로 검증했으며 native·S3 실험을 다시 실행하지 않았다.
