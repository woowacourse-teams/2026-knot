## 현재 위치

**번호를 붙인 개선안 5개는 모두 실험했고, 최종 반영 범위는 1·2·4와 스케줄러 수정이다. 3·5는 보류한다.** 개선안 5 import만 제외하고 develop D를 병합했으며 공통 리포트 보존 W와 A/B 소스를 고정했다. 연결·시계 진단은 결과와 한계를 기록하고 종료했다. GitHub Actions 전체 CI가 실제로 얼마나 줄었는지는 아직 검증하지 않았다.

최종 실행 계획: [Backend CI 최종 변경 범위와 비교 기준선 확정](../implement-plan/715-final-ci-baseline.md). [코드 정리 결과](715-ci-final-baseline.md): develop D `0c0c4e64e`, 병합 HEAD `10b207a70`에 이어 개선안5 제외 `f1c653d75`·공통 리포트 보존W `29bf52bad`를 커밋하고 작업 브랜치에 push했다. 스케줄러 수정을 전후 양쪽에 적용하고 1·2·4 여부만 다른 A/B tree·archive를 보존했다. 코드 정리 시점의 대상·전체 테스트·Actions 실행은0회였으며 이후 검증 상태는 아래와 같다.

후속 [최종 B 대상·격리 검증](715-ci-final-isolation.md)은 완료했다. 인증10·조회38·snapshot8의 단독/결합 정순·역순과 스케줄러 정상3·오염1을 실행했다. 정상20회·171건 성공, 예상한 부정 사례1건 실패·원본 보존, 기록 대조401/401 통과다. 이어 [일반 전체 회귀](715-ci-final-regression.md)도 정확히1회 실행해 Spotless·단위1543·통합676·인수567·bootJar가 모두 통과했다. 총2786건 실패/오류/스킵0, 명령308.778초, 사후대조26/26이다. 위 0회 표시는 코드 정리 당시 기록이며 Actions는 여전히0회다. fetch된 새 origin/develop을 이번 고정 B에 혼합하지 않았다.

실험 횟수나 문서 수를 분모로 전체 진행률을 계산하지 않는다. 남은 컨텍스트 32개도 모두 합칠 수 있는 미완료 작업 32개라는 뜻이 아니다. 검증 목적상 유지해야 하는 설정 차이가 포함된다.

## 4. 얼마나 남았는가

**진단 R1·최종 코드 정리 R3·최종 로컬 회귀는 완료했다. 남은 핵심 작업은 실제 Actions 비교 → 성과 문서의 2묶음이다.** 최종 코드 2커밋은 push했고, [Actions A/B 실행 계획](../implement-plan/715-actions-ab-comparison.md)을 작성했다. 비교용 원격 ref/PR 준비는 후속이다. R4는 최종 CI의 단계·느린 클래스 분류로 한정한다. 원인 수정 R2는 최종 검증에서 장애가 다시 나타날 경우 필요한 조건부 작업이다. 이 묶음 수를 완료율로 바꾸지 않는다. 진단 종료는 DB 장애 해결을 뜻하지 않는다.

| 순서 | 남은 묶음 | 완료 조건 | 상태 |
| --- | --- | --- | --- |
| R1 | DB 전달 구간 진단 | 새 관측 사전 검증 후 전체 3회. 도달 단계 또는 미확정·수집 한계를 기록 | **3/3회·결과 기록 완료. timeout 미재현, C3 시계 조건으로 관측 일부 불완전. 추가 실행 없음** |
| R2 | 확인한 원인의 최소 수정 | 원인이 좁혀진 경우 수정과 기존 검증·격리·반복 회귀 확인 | **조건부. 원인·작업량 미확정** |
| R3 | 개선안 5 최종 결정 | 보류한 후보를 제외하고 1·2·4·스케줄러 및 develop 공통 기준선을 정리 | **코드 제외·D 병합·공통W·A/B 소스 고정·정적 대조·최종 코드2커밋/push 완료** |
| R4 | 인수·SSE·준비/정리 비용 점검 | 최종 CI 단계·느린 클래스로 남는 비용 분류. 새 개선 실험은 이번 범위에서 추가하지 않음 | 최종 비교와 함께 진행 예정 |
| R5 | 최종 회귀와 실제 GitHub Actions 비교 | 최종 채택 코드의 Spotless·단위·통합·인수·bootJar 검증, 같은 workflow/runner/캐시 기준의 CI 전후 측정 | **대상·격리·스케줄러 정상3/오염1·일반 전체 회귀1회 완료. Spotless·2786건·bootJar 통과. Actions는 미실행** |
| R6 | 최종 정리·블로그·이력서 | 대상 실험 효과와 실제 CI 효과를 구분하고, 채택/보류 이유·실패·한계를 최종 문서로 정리 | 미완료 |

이전 전달 구간 진단의 로컬 전체 통합 **3회는 실행 완료**했다. 추가 시계·네트워크 재현이나 개선안 5 전후 로컬 6회를 이번 마무리의 필수 작업으로 추가하지 않는다. 최종 후보의 대상 격리·일반 전체 회귀1회는 완료했고 실제 Actions 전후 각3회 비교가 남았다. 스케줄러와 리포트 보존을 공통 적용하고, 같은 develop SHA·runner/캐시 조건으로 비교한다. 기존649개 목록·과거 시간으로 새 기준선을 대체하지 않는다. 원격 비교 실행은 아직 수행하지 않았다.

후속 [C3 시계 분석·작은 검증 계획](../implement-plan/715-db-connection-clock.md)에 따른 [보조 판정 검증 결과](715-db-connection-clock.md)를 기록하고 종료했다. fixture 15개와 기존 C1~C3 재생 1묶음으로 두 수집 종료 뒤의 변화와 구간 내 일관성을 분리했다. C3 두 구간은 관측 표본에서 일관됐고, C1·C2 한 구간씩은 독립 heartbeat 부족으로 미확인이다. 기존 판정·원본을 유지했고 새 전체 통합·DB·패킷 수집은 0회다. OS 시간 서비스나 A3 장애 원인은 미확정으로 남기며 추가 진단 반복은 계획하지 않는다.

사용자가 확정한 마무리 경로는 5를 이번 반영에서 보류하고, **최종 코드·기준선 확정 → 최종 회귀·Actions 비교 → 결과 정리**로 진행하는 것이다. 코드 정리·소스 고정·최종 로컬 회귀는 완료했고 실제 Actions 비교와 최종 성과 정리가 남았다. 이번 로컬308.778초를 과거CI7분13초와 직접 비교한 개선율로 사용하지 않는다.

진단이 길어진다고 개선안 5를 반드시 채택할 때까지 반복하지 않는다. 원인을 확정하지 못하면 후보를 제외하고 1·2·4와 스케줄러 수정의 검증된 범위로 CI 비교를 진행할 수 있다. 다만 간헐 실패가 최종 검증에 남으면 성공한 실행만 골라 CI 개선 완료로 표시하지 않는다.

현재 Backend CI는 PR 또는 main/develop push에서 실행된다. 작업 브랜치 push를 CI 성능 측정으로 간주하지 않는다. 후속 요청에 따라 최종 코드를 커밋/push했고 Issue #715의 BE·Refactor·흑곰 라벨과 assignee jyt6640을 확인했다. 비교용 ref/PR·Actions는 아직 만들거나 실행하지 않았다. Issue 본문/체크박스는 변경하지 않았다.

## 지금 블로그·이력서에 쓸 수 있는 범위

“Spring 컨텍스트 설정 차이와 캐시 퇴출에 따른 DB/Flyway 반복 초기화를 계측하고, 호환 가능한 테스트 그룹의 설정을 정렬해 기존 검증과 데이터 격리를 유지하면서 초기화 횟수를 줄였다. 대상 그룹별 로컬 실행에서는 시간 감소를 확인했으나, 전체 CI 개선율은 실제 Actions 비교 전이므로 확정하지 않았다.”

**“CI 7분 → 몇 분”이라는 최종 성과 수치는 아직 없다.** 현재 완료된 것은 반복 초기화의 원인 규명·일부 제거·격리 검증과, 간헐 연결 실패를 분석할 증거 확보다.
