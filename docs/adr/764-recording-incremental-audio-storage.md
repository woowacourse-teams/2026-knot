# 녹음 중 조각을 서버에 저장하고 종료 후 서버에서 최종 음원을 생성한다

## 상태

Proposed

## 관련 Issue

- #764 [BE] 녹음 중 오디오 조각 저장

## 한 줄 요약

녹음 중 조각을 서버에 저장하고 종료 후 서버에서 최종 음원을 생성한다

## 왜 이 결정이 필요했나

기존 종료 후 최종 WebM 업로드는 녹음 중 메모리 음성을 서버에 보존하지 않는다.

다음 주 출시 범위로 A: 기존 최종 파일 업로드 안정화와 B: 녹음 중 서버 전송·저장 추가를 비교했다.

결정 동인:

- 녹음 중 서버 저장을 이번 출시 필수로 충족한다.
- 정상 온라인 미저장 목표 5~10초를 실측할 수 있게 한다.
- PC Chrome 우선으로 기존 저장소·AI 경로를 재사용한다.

## 트레이드 오프

- A: 종료 후 최종 파일 업로드를 유지하며 저장 실패와 응답 유실을 안정화한다. 구현 범위는 작지만 녹음 중 서버 보존 요구를 충족하지 못한다.
- B(선택): 녹음 중 서버 전송·저장을 추가한다. 조각·최종화·재시도·정리 계약이 추가되지만 종료 전 음성을 보존한다.

## 무엇을 결정했나

녹음 중 조각을 서버에 저장하고 종료 후 서버에서 최종 음원을 생성한다

녹음 중 저장을 출시 필수 범위로 정했으므로 종료 시점에만 전송하는 기존 경로로는 요구를 충족하지 못한다. PCM16LE·16kHz·mono 5초 조각, 조건부 S3 PUT과 version 검증, 종료 후 WAV 생성은 사용자에게 위임받은 기술 설계다. 실제 비교한 제품 대안과 구분한다.

## 결과

- 세션의 audioMode는 불변이며 기존 WebM 모드와 조각 모드를 혼용하지 않는다.
- 조각 identity와 exact version을 저장하고 ACK는 검증·DB 커밋 뒤 반환한다.
- 종료·seal(#765), DB 대기열(#766), WAV 최종화·전사(#767), 보관·폐기(#768)가 같은 결정을 참조한다.
- 신규 PCM 시작은 기본 비활성이며 전체 통합 검증 뒤 활성화한다.

## 다시 논의해야 할 조건

- PC Chrome 이외의 브라우저를 공식 지원할 때
- 정상 온라인 저장 지연 목표 또는 인프라·비용 제약이 달라질 때
