# 신규 안건 문서만 별도 큰 주제에 배정한다. WRITE_BODY/ASSIGN_CATEGORY/PUBLISH를 저장하고 본문과 배정을 함께 공개한다. 배정 AI 장애는 제한 재시도와 서버 규칙 분류 및 최후 기타로 완료한다.

## 상태

Proposed

## 관련 Issue

- #913 [BE] 새 문서의 큰 주제 자동 배정과 배정 실패 복구 구현

## 한 줄 요약

신규 안건 문서만 별도 큰 주제에 배정한다. WRITE_BODY/ASSIGN_CATEGORY/PUBLISH를 저장하고 본문과 배정을 함께 공개한다. 배정 AI 장애는 제한 재시도와 서버 규칙 분류 및 최후 기타로 완료한다.

## 왜 이 결정이 필요했나

안건별 topic이 폴더 이름과 생성 식별값을 겸해 장기적으로 재사용할 큰 주제로 묶기 어렵다.

여러 회의의 문서가 세부 안건 이름의 한 문서짜리 폴더로 쌓여, 관련 문서가 하나의 큰 주제 아래 모이지 않는다.

결정 동인:

- 여러 회의의 관련 문서 탐색
- 안건별 문서·Job 식별과 기존 자료 보존
- 본문과 큰 주제 동시 제공
- 배정 장애 후 작성 결과 재사용

## 트레이드 오프

- 미분류로 본문을 먼저 공개한 뒤 배정: 빠른 공개가 가능하지만 본문과 큰 주제가 함께 제공되지 않는다.
- 배정 AI 성공까지 대기: 분류 품질을 모델에 맡길 수 있지만 AI 장애가 본문 공개를 무기한 막는다.
- 유효 본문 보관 후 제한 배정 재시도·서버 규칙 분류·최후 기타로 원자적 공개: 가용성을 확보하되 일부 문서의 분류 품질을 양보한다.

## 무엇을 결정했나

신규 안건 문서만 별도 큰 주제에 배정한다. WRITE_BODY/ASSIGN_CATEGORY/PUBLISH를 저장하고 본문과 배정을 함께 공개한다. 배정 AI 장애는 제한 재시도와 서버 규칙 분류 및 최후 기타로 완료한다.

사용자는 기존 문서 보존, 본문과 배정의 동시 공개를 선택했다. 이후 배정 AI 장애에 무기한 대기하지 않도록 서버 대체 분류와 최후 수단 기타를 허용했다.

## 결과

- 기존 문서와 안건 topic을 보존하고 새 문서만 큰 주제 하나에 연결한다.
- 기존 API 경로·요청·응답 구조와 화면을 유지한다. 목록의 topics와 카드 topic에 큰 주제 표시 이름을 내리고 원래 안건은 내부에 보존한다.
- 기존 세부 주제와 새 큰 주제의 표시 이름이 같으면 화면에서는 한 그룹으로 집계하지만 기존 문서의 저장 소속을 변경하지 않는다.
- 임시 본문·배정 예산·완료 결정을 저장해 재시작이나 DB 저장 실패 때 LLM을 반복 호출하지 않는다.
- 규칙과 기타는 AI 장애 시 가용성을 높이지만 의미 분류 품질은 실제 모델 평가와 fallback 비율 관측이 필요하다.
- Backend/DB 장애 중 즉시 성공이나 본문 생성 자체의 성공을 보장하는 정책은 아니다。

## 다시 논의해야 할 조건

- 기존 문서 재정리 또는 수동 이동·주제 병합 기능을 도입할 때
- 큰 주제 후보 증가로 context 한도·지연·중복 문제가 관측될 때
