# GitHub OAuth 신원과 Member 지연 생성 정책

> ADR 형식을 보여주는 가상 예시다. 실제 대화에서 확인되지 않은 추가 문답을 사용했으며,
> 실제 `backend/docs/adr`의 결정 기록이나 materializer의 정확한 출력이라고 주장하지 않는다.

## 상태

Proposed

## 관련 Issue

- #10 [BE] OAuth 사용자 계정 식별 및 회원가입 구현

## 한 줄 요약

GitHub OAuth로 확인한 신원을 가입 세션에 보관하고, 닉네임 입력을 완료하면 Member를
한 번만 생성한다.

## 왜 이 결정이 필요했나

OAuth 콜백에서 Member를 바로 생성하면 닉네임 입력을 중단한 사용자의 불완전한 계정이
남는다. 클라이언트가 `githubId`를 보관하고 다시 보내게 하면 외부 신원을 클라이언트
입력으로 신뢰하게 된다.

회의에서는 OAuth 콜백 즉시 생성, 클라이언트가 GitHub 신원을 다시 전송하는 방식, 서버
가입 세션을 실제 대안으로 검토했다.

결정 동인:

- 닉네임 입력을 마치지 않은 Member를 남기지 않는다.
- GitHub 신원을 클라이언트 입력으로 신뢰하지 않는다.
- 닉네임 오류는 OAuth 없이 다시 시도할 수 있어야 한다.
- 같은 GitHub 계정으로 Member가 둘 이상 생기지 않아야 한다.

## 트레이드 오프

- OAuth 콜백에서 Member 즉시 생성: 구현이 단순하지만 닉네임 입력을 완료하지 않은 Member가 남는다.
- 클라이언트가 `githubId`와 닉네임을 함께 전송: 별도 가입 세션이 필요하지 않지만 외부 신원의 신뢰 경계가 클라이언트까지 확장된다.
- 서버가 가입 세션을 발급하고 닉네임 완료 시 생성: 외부 신원을 서버에서만 신뢰할 수 있고, 불완전한 Member 생성을 막으면서 닉네임 입력을 재시도할 수 있다.

## 무엇을 결정했나

GitHub OAuth로 확인한 신원을 가입 세션에 보관하고, 닉네임 입력을 완료하면 Member를
한 번만 생성한다.

이 방식은 불완전한 Member 생성을 막으면서 신뢰 경계를 서버 안에 유지한다. 가입 세션이
유효하면 닉네임 입력부터 재시도하고, 만료되면 GitHub OAuth부터 다시 시작한다.

## 결과

- OAuth 콜백과 회원가입 완료 처리가 분리된다.
- 닉네임 입력 전까지 서버가 검증할 수 있는 가입 세션이 필요하다.
- 닉네임 검증 실패에서는 Member를 생성하지 않는다.
- 닉네임 중복을 허용한다.
- 같은 GitHub 계정의 동시 요청은 Member 한 명 생성으로 수렴해야 한다.

## 다시 논의해야 할 조건

- GitHub 이외의 로그인 제공자를 추가할 때
- 여러 OAuth 계정을 하나의 Member에 연결할 때
- 탈퇴 후 재가입이나 계정 복구 정책을 도입할 때
- 닉네임 없이 회원가입을 완료하도록 정책이 바뀔 때
