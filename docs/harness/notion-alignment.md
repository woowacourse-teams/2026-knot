# Notion·Issue·구현 정합성

[정본 목록](../../.agents/skills/knot-feature/references/sources.md)의 Notion과 Figma는 제품 요구사항,
GitHub Issue·PR·ADR은 결정과 작업 기록, 코드·테스트는 현재 구현의 근거다.

1. 작업과 관련된 원문 본문과 DB 속성을 직접 읽고 현재 기준·초안·지난 버전을 구분한다.
2. 관련 Issue·ADR·실제 코드와 비교한다. Notion의 구현 완료 표기를 코드 검증으로 대신하지 않는다.
3. 차이가 있으면 출처와 사용자 영향을 제시한다. 기능 요구사항 충돌은 `needs_user_input`으로
   반환하고 도메인 팀의 결정을 받는다. 제품 기획 기준 변경은 유월에게 승인을 받는다.
4. 정본 접근 실패나 부재는 `blocked`로 보고한다. 독립적으로 근거가 확인된 작업은 계속할 수 있다.
5. 승인된 변경은 해당 원문에서 관리하고 Issue·PR에는 링크와 변경 요약을 남긴다.

문서를 저장소 Markdown으로 복제하거나 로컬 수집·동기화를 기능 하네스의 선행 조건으로 삼지 않는다.
과거 대화나 수집 실행 기록을 팀 전체의 현재 정책으로 취급하지 않는다.
