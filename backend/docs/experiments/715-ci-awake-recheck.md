## 5. 새로 관측된 DB 연결 실패

| 실행 | 실패 클래스 | 클래스 Duration | 최초 실패 | 같은 컨텍스트 재로딩 제한에 따른 후속 실패 |
| --- | --- | ---: | ---: | ---: |
| 1회 | RecordingTranscriptionFlowIntegrationTest | **54.338초** | 1건 | 2건 |
| 2회 | DocumentGenerationResultIntegrationTest | **52.541초** | 1건 | 28건 |

두 실행의 최초 실패는 모두 다음 예외 흐름이었다.

```text
ApplicationContext 초기화
→ Flyway가 DB 연결 요청
→ PostgreSQL 연결 실패, SQL State 08001
→ SocketTimeoutException: Read timed out
```

스택의 읽기 timeout 위치는 PostgreSQL JDBC의 `ConnectionFactoryImpl.enableSSL()`이었다. SSL 없이 연결하는 fallback의 인증 경로에서는 suppressed `EOFException`도 관측됐다. **연결 수립 중 응답을 읽지 못한 사실까지 확인했으며, SSL 설정 자체가 원인이라고 확정하지 않는다.**

최초 컨텍스트 초기화 실패 이후 Spring의 `ApplicationContext failure threshold (1)`에 따라 같은 설정을 필요로 하는 후속 사례도 실패했다. 따라서3건·29건을 각각 독립적인 DB 장애3회·29회로 계산하지 않는다.

이 실패는 migration SQL 검증 실패나 기존 스케줄러 deadlock과 구분한다. 두 실패 클래스 모두3회차에서는 성공했다. 단독 성공이나3회차 성공으로 앞선 실패를 해소됐다고 처리하지 않았다.

## 7. 호스트 메모리 관측과 한계

| 호스트 전체 지표 | 1회 | 2회 | 3회 |

높은 swap 사용량뿐 아니라 실제 교체 카운터 증가도 관측됐다. 절전은 통제했지만 다른 앱·QA 작업을 포함한 호스트 메모리 사용까지 통제한 실험은 아니다.

위 수치는 호스트 전체 누적 카운터의 표본 간 차이다. 테스트 JVM만의 사용량이나 물리 디스크 I/O 바이트 수가 아니다. 실행 길이도 서로 다르며, 이 표만으로 메모리 압박이 DB 연결 실패를 유발했다고 확정할 수 없다. QA 컨테이너나 관측 도구의 영향도 분리해 입증하지 않았다.

GC·safepoint 로그, PostgreSQL 서버 로그, Docker 포트 전달 단계의 연속 기록은 이번 실험에서 추가 수집하지 않았다. heartbeat가 정상이라는 사실만으로 모든 짧은 GC나 DB 대기를 배제하지 않는다.

추가 진단 기준인 클래스10초 초과에는 `DocumentGenerationExecutionIntegrationTest`도3회 모두 해당했다. 코드·사례 시간을 대조하면 Workspace 잠금 대기3초 제한을 검증하는3개 사례가 각각 약3.03~3.09초를 사용했다. 기존 잠금 timeout 검증을 위해 필요한 비용이며 이번 실험에서 제거하지 않았다.

1. 절전 방지를 유지하고, 메모리 경쟁을 줄일 수 있는 별도 실행 시간대와 작업 조건을 확보한다. 다른 사용자 작업을 임의 종료하지 않는다.
2. 실패 시 컨테이너 ready·실제 mapped endpoint·JDBC 연결 시작/종료·PostgreSQL 서버 로그를 같은 시각으로 보존한다. SSL 협상과 fallback 경로의 실패를 구분하되 SSL을 끄는 변경을 곧바로 해결책으로 채택하지 않는다.

4. 안정된 조건이 마련되면 양쪽에 같은 스케줄러 수정과 관측 설정을 적용한 새 전후 각3회 비교로 개선안5의 채택을 판단한다.

- `analyze_awake.py`, `analysis.json`, `audit.json`: 집계와 검증 판정. 전체 검증 및 기대 초기화 구조에 대한 실패 항목도 숨기지 않고 보존

실제 Gradle 결과와 Persona 도구 인증은 구분한다. implementation·review report-filled는 통과했고, `workflow finish implement`는 `source-read-runtime-unavailable`로 종료됐다. 기존 환경·이력을 초기화하지 않았으며 Persona 최종 인증을 받았다고 주장하지 않는다. 이는 위에 기록한 실제 테스트2회 실패·1회 성공과 별도 판정이다.
