## 현재 위치

**번호를 붙인 개선안 5개와 실제 Actions 전후 각 3회 비교를 완료했다. 최종 채택 범위는 1·2·4와 스케줄러 수정이고, 3·5는 보류한다.** 공통 develop D·스케줄러 수정·리포트 보존 W를 고정했다. Actions 여섯 실행 모두 통과했고 통합 단계의 Spring·PostgreSQL·Flyway 초기화 로그가 각각 7건 줄었다. 전체 job 중앙값은 423→418초로 약 1.2% 감소했으나 범위가 겹쳐 안정적인 전체 CI 단축은 입증하지 못했다. [실제 Actions 비교 결과](715-ci-actions-ab-comparison.md)에 원시값·환경·판정·보존 근거를 기록했다. 연결·시계 진단은 한계를 기록하고 종료했다.

최종 실행 계획: [Backend CI 최종 변경 범위와 비교 기준선 확정](../implement-plan/715-final-ci-baseline.md). [코드 정리 결과](715-ci-final-baseline.md): develop D `0c0c4e64e`, 병합 HEAD `10b207a70`에 이어 개선안5 제외 `f1c653d75`·공통 리포트 보존W `29bf52bad`를 커밋하고 작업 브랜치에 push했다. 스케줄러 수정을 전후 양쪽에 적용하고 1·2·4 여부만 다른 A/B tree·archive를 보존했다. 코드 정리 시점의 대상·전체 테스트·Actions 실행은0회였으며 이후 검증 상태는 아래와 같다.

후속 [최종 B 대상·격리 검증](715-ci-final-isolation.md)은 완료했다. 인증10·조회38·snapshot8의 단독/결합 정순·역순과 스케줄러 정상3·오염1을 실행했다. 정상20회·171건 성공, 예상한 부정 사례1건 실패·원본 보존, 기록 대조401/401 통과다. 이어 [일반 전체 회귀](715-ci-final-regression.md)도 정확히1회 실행해 Spotless·단위1543·통합676·인수567·bootJar가 모두 통과했다. 총2786건 실패/오류/스킵0, 명령308.778초, 사후대조26/26이다. 위 0회 표시는 코드 정리 당시 기록이며 이후 Actions 6회도 모두 성공했다. fetch된 새 origin/develop을 이번 고정 B에 혼합하지 않았다.

실험 횟수나 문서 수를 분모로 전체 진행률을 계산하지 않는다. 남은 컨텍스트 32개도 모두 합칠 수 있는 미완료 작업 32개라는 뜻이 아니다. 검증 목적상 유지해야 하는 설정 차이가 포함된다.

## 3. 초기 가설별 진행 상황

| 초기 가설 | 현재 결론 | 남은 범위 |
| --- | --- | --- |
| 1. 설정 차이에 따른 컨텍스트 분리 | 실제 원인으로 확인. 호환 가능한 일부 그룹은 설정 정렬로 공유 | 모든 설정이 공유 가능하다는 뜻은 아님 |
| 2. 컨텍스트에 동반되는 PG/Flyway 반복 초기화 | 실제 동반 반복과 감소 확인 | 반드시 필요한 DB·migration 검증은 유지 |
| 3. 캐시 퇴출 뒤 같은 설정 재생성 | 메커니즘 확인 | 캐시 확대의 전체 시간·자원 이점은 채택 기준 미충족 |
| 4. 테스트 내부 준비·정리·대기 | 스케줄러 초기 정리 개선. 최종 CI에서 초기 클래스 준비·SSE 종료 대기·의도한 heartbeat/timeout 검증으로 남는 비용 분류 | 단계·클래스 분석 완료. 세부 작업별 계측이나 새로운 SSE 최적화는 별도 후보 |

연결 timeout은 위 네 가설과 별도로 드러난 안정성 문제다. 원래 네 가설 중 하나를 억지로 원인으로 붙이지 않는다.

## 4. 얼마나 남았는가

**최종 코드·로컬 회귀·Actions 전후 각 3회·별도 결과 문서까지 완료했다.** R4는 단계·느린 클래스 분류로 마쳤고 R5는 여섯 실행 모두 성공했다. 남은 것은 결과를 블로그·이력서 문장으로 편집하는 R6이며, 비교용 Draft PR의 develop 병합은 이번 실행 범위에 포함하지 않았다. 원인 수정 R2는 장애가 다시 발생해 원인이 좁혀진 경우의 별도 작업이다. 이 묶음 수를 완료율로 바꾸지 않으며 진단 종료를 DB 장애 해결로 해석하지 않는다.

| 순서 | 남은 묶음 | 완료 조건 | 상태 |
| --- | --- | --- | --- |
| R1 | DB 전달 구간 진단 | 새 관측 사전 검증 후 전체 3회. 도달 단계 또는 미확정·수집 한계를 기록 | **3/3회·결과 기록 완료. timeout 미재현, C3 시계 조건으로 관측 일부 불완전. 추가 실행 없음** |
| R2 | 확인한 원인의 최소 수정 | 원인이 좁혀진 경우 수정과 기존 검증·격리·반복 회귀 확인 | **조건부. 원인·작업량 미확정** |
| R3 | 개선안 5 최종 결정 | 보류한 후보를 제외하고 1·2·4·스케줄러 및 develop 공통 기준선을 정리 | **코드 제외·D 병합·공통W·A/B 소스 고정·정적 대조·최종 코드2커밋/push 완료** |
| R4 | 인수·SSE·준비/정리 비용 점검 | 최종 CI 단계·느린 클래스로 남는 비용 분류. 새 개선 실험은 이번 범위에서 추가하지 않음 | **분류 완료. 초기 클래스 준비·SSE 종료 대기·의도한 timeout 검증. 세부 비용은 미계측** |
| R5 | 최종 회귀와 실제 GitHub Actions 비교 | 최종 채택 코드의 Spotless·단위·통합·인수·bootJar 검증, 공통 workflow·이미지·캐시 기준의 CI 전후 측정 | **로컬 대상·전체 회귀 완료. Actions 6/6 성공·누적16,716건·보존41/41. 초기화 각각7건 감소, 전체 중앙값 약1.2% 감소 관찰·안정적 단축 미입증** |
| R6 | 최종 정리·블로그·이력서 | 대상 실험 효과와 실제 CI 효과를 구분하고, 채택/보류 이유·실패·한계를 최종 문서로 정리 | **별도 결과 문서 완료. 블로그·이력서용 편집은 후속** |

이전 전달 구간 진단의 로컬 전체 통합 **3회는 실행 완료**했다. 추가 시계·네트워크 재현이나 개선안 5 전후 로컬 6회를 이번 마무리의 필수 작업으로 추가하지 않는다. 최종 후보의 대상 격리·일반 전체 회귀1회와 실제 Actions 전후 각3회 비교까지 완료했다. 스케줄러와 리포트 보존을 공통 적용하고 같은 develop SHA·workflow·runner 이미지·캐시로 비교했다. 물리 호스트는 통제하지 못했다. 기존649개 목록·과거 시간으로 새 기준선을 대체하지 않았다.

후속 [C3 시계 분석·작은 검증 계획](../implement-plan/715-db-connection-clock.md)에 따른 [보조 판정 검증 결과](715-db-connection-clock.md)를 기록하고 종료했다. fixture 15개와 기존 C1~C3 재생 1묶음으로 두 수집 종료 뒤의 변화와 구간 내 일관성을 분리했다. C3 두 구간은 관측 표본에서 일관됐고, C1·C2 한 구간씩은 독립 heartbeat 부족으로 미확인이다. 기존 판정·원본을 유지했고 새 전체 통합·DB·패킷 수집은 0회다. OS 시간 서비스나 A3 장애 원인은 미확정으로 남기며 추가 진단 반복은 계획하지 않는다.

사용자가 확정한 마무리 경로는 5를 이번 반영에서 보류하고, **최종 코드·기준선 확정 → 최종 회귀·Actions 비교 → 결과 정리**로 진행하는 것이다. 이 경로의 실행과 별도 결과 문서를 완료했다. 블로그·이력서 편집 시에도 로컬308.778초를 과거CI7분13초와 직접 비교한 개선율로 사용하지 않는다.

진단이 길어진다고 개선안 5를 반드시 채택할 때까지 반복하지 않는다. 원인을 확정하지 못하면 후보를 제외하고 1·2·4와 스케줄러 수정의 검증된 범위로 CI 비교를 진행할 수 있다. 다만 간헐 실패가 최종 검증에 남으면 성공한 실행만 골라 CI 개선 완료로 표시하지 않는다.

현재 Backend CI는 PR 또는 main/develop push에서 실행된다. 작업 브랜치 push를 CI 성능 측정으로 간주하지 않는다. 최종 코드 커밋/push 후 공통 base·A·B 원격 ref를 고정하고 비교용 Draft PR [#754](https://github.com/woowacourse-teams/2026-knot/pull/754)·[#756](https://github.com/woowacourse-teams/2026-knot/pull/756)에서 실제 Actions 각3회를 수행했다. Issue와 두 PR의 BE·Refactor·흑곰 라벨 및 assignee jyt6640을 확인했다. Issue 본문/체크박스와 develop은 변경하지 않았다. 결과 문서는 추가 CI를 유발하는 head 이동 없이 로컬에 작성했다.
