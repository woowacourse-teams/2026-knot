# 백엔드 Notion 근거 확인

백엔드 기획·구현·리뷰는 [하네스 정본 목록](../../.agents/skills/knot-feature/references/sources.md)의
기능 요구사항·도메인 규칙·API 명세를 직접 읽는다. 연결 방법은
[MCP 접근 설정](../../docs/harness/mcp-access.md)을 따른다.

1. 사용자 요청·Issue에서 기능, API 경로, 엔티티와 성공·실패 조건을 식별한다.
2. 관련 Notion 페이지의 본문·상태·필요한 DB 속성을 읽는다.
3. 현재 계약과 초안·논의 중·과거 기록을 구분한다. 제목이나 수정 시각만으로 확정 여부를 판단하지 않는다.
4. Issue·ADR·코드·테스트와 대조한다. 원문은 요구사항의 근거이고 코드는 현재 구현의 근거다.
5. Issue·PR에는 확인한 원문 링크와 변경 요약을 남긴다. 문서 전문은 저장소로 옮기지 않는다.

접근 불가·정본 부재는 `blocked`, 요구사항 충돌이나 제품 판단은 `needs_user_input`으로
입구 스킬에 반환한다. 필요한 근거를 과거 캐시나 개인 문서로 대신 확정하지 않는다.
