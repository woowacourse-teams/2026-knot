## 백엔드 원문 동기화 진입점 · 2026-10-08

백엔드 작업은 [관련 Notion 근거 탐색 기준](../notion-context.md)을 따른다.
`backend/docs/notion/`은 Git에서 제외한 원문 캐시이며 전체를 정제한 하네스 문서가 아니다.
구현 계획에서는 관련 문서만 찾아 읽고 적용할 사실과 출처를 선별한다.
기획 모음 전체·(신)도메인 지정 5개 페이지와 하위 페이지·(신)API 전체의 본문과 DB 속성을 포함한다.
수집 실행 이력과 파일 수는 [Notion 문서 동기화의 과거 관측](../../../docs/harness/notion-docs-sync.md#과거-수집-관측--2026-10-08)에 기록한다. 제품 요구사항으로 해석하지 않는다.
현재 scope/누락/revision은 로컬 manifest와 coverage를 따른다. 아래 10/6 이전 queue 수치는 과거 관측이다.
원문 사본의 수집 완료는 제품 승인·Issue 완료·실제 구현 완료를 의미하지 않는다.
갱신 절차는 [Notion 문서 동기화](../../../docs/harness/notion-docs-sync.md)를 따른다.

이 문서는 기획·구현·리뷰에서 현재 작업에 적용할 원문을 찾는 진입점이다.
제품 정책 전문은 Notion 원문에서 관리한다. 이 문서의 범위 요약이나 과거 구현을
새로운 제품 결정의 근거로 사용하지 않는다.

- 관련 작업: [#374](https://github.com/woowacourse-teams/2026-Knot/issues/374)
- 최신 대조: 2026-10-06, 운영 Notion의 n8n capture와 문서 API, GitHub #495·#496 확인.
  사용자가 최신 API 명세를 우선 기준으로 지정했다. 아래 `2026-10-06 최신 API 기준` 절을 따른다.
- 최신 capture: 2026-10-06 11:27:43 KST, source 820개. 변경 후보 20개를 수집했고,
  초대 제외 항목 2개의 비교를 완료한 초기 queue는 pending 199개·processed 9개였다.
  수집 workflow는 미게시 초안의 수동 실행, 완료 workflow는 게시 상태였다.
- 최종 queue 대조: 2026-10-06 12:26:40 KST, 이후 71개를 추가 완료해 pending 128개·
  processed 80개·verified 0개다. 199개 모두의 판정을 기록했고 보류 조건은 아래 checkpoint에 둔다.
- 이전 자료 확인: 2026-10-01, 운영 Team Notion·n8n Data Table·GitHub Issue 확인
- 이전 원문 시점: 도메인 규칙은 운영 Notion에서 확인. API 세부 후보는 2026-09-30 07:16 UTC
  (16:16 KST)에 감지된 n8n 대기 항목 기준
- 이전 n8n 관측: 10/1 14:32 KST에는 741 source와 37 queue row가 모두 `pending`이었다. 15:00
  KST 재확인에서는 14개가 `processed`, 23개가 `pending`, `verified`는 0개였다. 마지막
  `captured_at`은 9/30 16:16 KST다. `Knot Notion Change Queue` 편집기는 15:00에도
  `Publish`를 표시해 미게시 상태였고, 새 capture는 확인되지 않았다. 별도
  `Knot Notion Queue Completion`은 게시된 5분 예약 workflow이며 최신 화면에서 성공 상태였다.
  15:24 KST 수동 capture는 `Get many child blocks`의 429 rate limit 오류로 멈췄고 upsert 전이라
  Data Table은 갱신되지 않았다. 처리 대상과 row별 근거는 [정합성 워크플로](../../../docs/harness/notion-alignment.md)
  checkpoint에 둔다.
- 상태 주의: API 세부 후보는 대기열에 남아 있으며 팀의 최종 승인이나 구현 완료를
  뜻하지 않는다. 최신 수집 상태와 검토 절차는 [Notion 정합성 워크플로](../../../docs/harness/notion-alignment.md)를 따른다.

## 작업 시작 순서

1. 현재 사용자 지시와 연결된 Issue의 범위를 확인한다. 사용자 지시로 정한 범위가
   팀 문서와 다르면 작업에 적용한 지시와 팀 문서에 남은 충돌을 구분해 기록한다.
2. 아래 출처표에서 해당 도메인의 원문과 변경 로그를 읽는다. 문서 제목의 `V2`,
   `최종`, `확정` 또는 수정 시각만으로 적용 여부를 결정하지 않는다.
3. 해당 항목이 현재 MVP에 포함되는지, 이전 결정을 명시적으로 대체했는지,
   충돌 목록에 남아 있는지 확인한다. Issue에 근거 문서·항목·확인 날짜를 남긴다.
4. 같은 항목의 출처가 충돌하면 아래 최신 API 우선 규칙과 이미 확인한 사용자 결정을
   먼저 적용한다. API에도 미정이거나 접근할 수 없으면 판단을 보류하고 영향 범위와
   확인할 질문을 적는다. [Notion 정합성 워크플로](../../../docs/harness/notion-alignment.md)에 따라
   Notion 주장, 저장소 문서, Issue와 실제 코드를 나란히 제시해 사용자 결정을 받는다.
   과거 문서나 AI 추론으로 빈 정책을 채우지 않는다. 확정 근거가 있는 독립 작업은 계속한다.
5. 제품 범위 확인 후 기존 API 계약·ADR·백엔드 컨벤션을 함께 적용한다.
   제품 기획의 빈 항목만으로 이미 있는 구현 계약을 폐기하지 않는다.

## 왜 현재 범위를 구분하는가

V1의 Notion 수집·검색 구현과 초기 V2의 공동 녹음·동시 편집 기획이 자료에 함께 남아 있다.
[변경 로그]의 2026-09-22 항목은 현재 V2가
녹음 → STT 전사 → 요약·문서 아카이빙 → 탐색에 집중하도록 범위를 줄였다고 설명한다.
공동 녹음과 여러 세션에 참여하는 흐름은 이후 버전으로 이동했다.
2026-09-23 항목은 도메인 규칙을 이 범위에 맞추면서 남은 충돌도 별도로 표시했다.

[#372](https://github.com/woowacourse-teams/2026-Knot/issues/372)는 V1 채팅·검색·Notion
구현 제거 작업이다. 제거 사실은 V2 대체 기능이 구현됐다는 뜻이 아니다.
인증·회원·워크스페이스·멤버십·초대와 공통 기반은 유지 대상으로 구분됐다.

## 현재 MVP 범위 요약

### 2026-10-06 최신 API 기준

사용자가 운영 Notion의 API 명세가 가장 최신이며 API를 기준으로 이해하도록 지정했다.
같은 항목을 명시적으로 다루는 최신 API가 도메인·ERD·화면 정책·이전 저장소 요약과
다르면 최신 API의 규칙을 현재 작업 기준으로 사용한다. 이미 해소한 출처 우선순위를
다시 질문하지 않는다. API가 다루지 않은 기능을 제외했다고 추론하거나 API 본문에
미정·제안으로 남은 값을 확정하지 않는다. 실제 구현·배포와 팀 리뷰 상태는 별도 확인한다.

[문서 목록 API](https://www.notion.so/3ebb435175228015bf4dc8d04281b461)와
[문서 상세 API](https://www.notion.so/3ebb4351752280289a59e5e52a060471)는
10/6 11:27:43 KST capture에서 확인했다. 두 페이지의 수정 시각은 각각
10/6 10:39·10:37 KST이며, 다음 규칙이 기존 `문서 상태 없음` 요약을 대체한다.

- 문서는 생성 완료 즉시 읽기 전용 `DRAFT`로 저장한다.
- 생성 시점의 Workspace 멤버를 확인 대상으로 고정한다. 이후 가입자는 읽을 수 있지만
  확인 대상에 추가하지 않으며 `myConfirmationState=NOT_REQUIRED`다.
- 모든 필수 대상이 확인하거나 미확인 탈퇴 대상으로 제외되면 `ARCHIVED`로 전환한다.
- 목록은 두 상태를 모두 조회한다. 상세는 `status`와 nullable `archivedAt`을 반환한다.
- 내 확인 상태는 `PENDING`·`CONFIRMED`·`NOT_REQUIRED`, 집계는 확인·미확인·제외 수다.

열린 [#495](https://github.com/woowacourse-teams/2026-Knot/issues/495)와
[#496](https://github.com/woowacourse-teams/2026-Knot/issues/496)도 이 상태·확인 계약을
포함한다. 이 대조와 사용자 결정은 구현 완료나 팀 리뷰 승인을 의미하지 않는다.
API의 페이지 크기 근거·DTO 제안 등 남은 미정은 해당 구현 범위에서 별도로 다룬다.

10/6 12:26:40 KST 전체 queue 판정에서는 199개 후보 중 비교 완료 71개를 처리했고,
본문·하위 DB 누락, API 내부 미정·실제 구현 차이와 연구 판정 불일치 등이 있는 128개를
보류했다. 이번 판정은 대체된 V1 기록이나 제안·실험을 현재 MVP 요구사항으로 승격하지
않는다. API 우선으로 정한 문서 상태·확인 규칙과 구현 완료 여부도 구분한다.
행별 완료/보류와 실제 queue 상태는
[전체 queue checkpoint](../../../docs/harness/notion-alignment.md#전체-199개-후보-판정-및-완료-처리-122640-kst)를 따른다.

### 2026-10-07 문서 생성 작업 목록 리뷰 반영

사용자가 PR #511의 두 리뷰를 모두 반영하도록 결정했다. 이 결정은 앞서 적용했던
개인 생성 작업 목록 API·Issue #493의 제목 응답과 Workspace 전체 Job 조회 규칙을 대체한다.

- `recordingTitle` 응답과 이를 위한 `RecordingSession.title`·미병합 V29 컬럼 추가를 제거한다.
  홈의 녹음 이름은 STT-R24의 ‘내 이름 님의 녹음’ 표시를 따른다.
- 현재 Workspace 멤버십을 확인한 뒤 호출자가 시작한 녹음의 Job만 반환한다.
  소유자 조건은 페이지 크기와 커서 계산 전에 DB 조회에 적용한다.
- 생성된 Document의 목록·상세·연결 원문 읽기 권한은 현재 Workspace 멤버 기준을 유지한다.
  Job 진행 목록의 소유자 제한을 문서 읽기 권한에 확대하지 않는다.
- 홈의 한 카드 선택·새 녹음 우선·종합 상태는 녹음 조회 계약과 연결한다.
  현재 `recordings/current` 구현은 RECORDING·PAUSED만 지원하므로 종료 후 처리 상태와
  작업 ID를 이미 제공한다고 표현하지 않는다.

근거는 사용자가 전달한 리뷰, GitHub #493·PR #511과 실제 코드, 10/6까지 수집한
변경 로그·STT-R24의 로컬 snapshot이다. 이번 Notion 실시간 fetch는 접근 404로

### 2026-10-03 초대 최소 MVP

### 2026-09-30 Workspace 정책 변경

사용자가 전달한 2026-09-30 팀 결정으로 다음 Workspace 정책을 적용한다.
이는 로컬 Notion 내보내기 사본의 기존 생성·탈퇴 규칙을 대체한다.

- OWNER의 Workspace 생성 개수에는 제한을 두지 않는다.
- 다른 멤버가 있는 OWNER는 승계할 활성 멤버를 선택한 뒤에만 탈퇴한다. OWNER 없는
  활성 Workspace를 만드는 탈퇴는 허용하지 않는다. (2026-10-05 변경: 아래 절 참조)
- 마지막 멤버가 나가면 Workspace를 논리 삭제한다.
- 생성 제한 [#396](https://github.com/woowacourse-teams/2026-Knot/issues/396)과
  [PR #406](https://github.com/woowacourse-teams/2026-Knot/pull/406)은 정책 폐기로 닫았다.
  PR은 병합하지 않았다. 후속 계약은 #397·#398·#403,
  [승계 후보 조회 #408](https://github.com/woowacourse-teams/2026-Knot/issues/408),
  [승계·탈퇴 #409](https://github.com/woowacourse-teams/2026-Knot/issues/409),
  [삭제 정책 #410](https://github.com/woowacourse-teams/2026-Knot/issues/410)에서 관리한다.

Notion 실시간 원문은 접근 실패로 동기화하지 못했다. 기존 최대 3개·OWNER 없는
Workspace 허용·마지막 멤버 탈퇴 후 유지 문구를 현재 정책으로 재사용하지 않는다.
녹음 중 삭제는 2026-09-30 담당자가 다음과 같이 선택했다. 마지막 멤버가 탈퇴해
Workspace가 삭제되는 경우, 해당 Workspace의 진행 중·일시정지 녹음은 강제로 종료하고
저장·전사·문서 생성 없이 폐기한다. 일반적인 본인 녹음 종료와 구분한다. 이 선택이 팀
Notion에 반영됐거나 팀 리뷰를 통과했다는 의미는 아니다. 다른 멤버가 남은 상태의 OWNER
삭제는 2026-10-05 정책 변경으로 없어졌다.

삭제된 Workspace의 녹음은 늦게 도착한 업로드·종료·복구 요청으로 저장하거나
다시 활성화하지 않는다. 녹음 탭에 종료를 알리는 것만으로 서버의 폐기 처리를
완료한 것으로 간주하지 않는다. 담당자는 사용자가 더 원하지 않는 데이터를 보존하기
위해 삭제를 기다리게 하는 UX를 피하려고 폐기 안을 선택했다. 기존 파일은 보존하며,
삭제 시 진행 중·일시정지 녹음본과 그 임시 오디오만 폐기한다. 기존 저장 오디오·전사·
문서의 물리 삭제·보존 기간은 변경하지 않는다. #397의 관련 미결정은 해소됐다.

### 2026-10-05 Workspace 삭제 정책 변경

담당자가 2026-10-05 다음과 같이 확정했다. 9/30 정책의 "OWNER는 승계하거나 삭제한다"를
대체한다. 결정 기록은 [ADR 410](../adr/410-workspace-deletion-only-by-last-owner-leave.md)이다.

- 다른 활성 멤버가 있는 Workspace에서 OWNER가 나가려면 반드시 승계할 멤버를 고른다.
  이 상태에서 Workspace를 삭제하는 경로는 두지 않는다.
- Workspace 논리 삭제는 OWNER 혼자 남은 상태에서 탈퇴할 때만 일어난다.
- 별도 Workspace 삭제 API(`DELETE /api/v1/workspaces/{workspaceId}`)는 만들지 않는다.
  삭제 API 단위 #470과 PR #471은 이 결정으로 닫았다.
- 이 정책을 바꾸려면 새 Issue와 ADR로 다시 결정한다. 기획·구현·리뷰에서 다른 멤버가 남은
  Workspace의 삭제 경로를 추가하지 않는다.

### 인증·로그인 정합 상태

`도메인 규칙 및 UseCase`는 GitHub OAuth, GitHub 계정당 Member 하나, 닉네임 입력 뒤 가입 완료,
닉네임 규칙, 기본 GitHub 프로필 이미지와 여러 Workspace 참여를 현재 도메인으로 적는다.
같은 도메인의 `아직 정하지 않은 것` 토글은 OAuth 세션·토큰 갱신·만료와 가입 중단 후
재진입을 미정으로 둔다. access 1시간, refresh idle 7일·absolute 30일, 회전·재사용 시
현재 로그인 계열 폐기와 현재 계열 로그아웃은 별도 API 명세와 9/30 candidate에 적혀 있지만,
이를 도메인 합의로 취급하지 않는다. 9/30 변경 로그에는 로그인 결정 항목이 없다. 이 문서 간
충돌은 남아 있다. 이 스레드에 제공된 도메인 발췌의
중복 요청 멱등성·닉네임 중복/변경 미정 항목은 현재 열린 Notion 미정 페이지에서 확인되지
않아 출처 차이로 기록한다.

2026-09-30 capture에는 GitHub OAuth callback, 닉네임 설정, refresh, logout API 후보가 있다.
네 후보는 검토 시작 시 모두 `pending`이었다. 10/1 열린 [#427](https://github.com/woowacourse-teams/2026-Knot/issues/427),
[#428](https://github.com/woowacourse-teams/2026-Knot/issues/428),
[#429](https://github.com/woowacourse-teams/2026-Knot/issues/429),
[#430](https://github.com/woowacourse-teams/2026-Knot/issues/430)은 사용자가 확인한 로그인 세션,
로그아웃, 닉네임 가입 완료, refresh 작업 범위를 기록한다. 이 Issue들은 팀 리뷰 승인이나
Notion 원문 정합 완료를 뜻하지 않는다. refresh API 본문은 204, CSRF, 7일·30일 만료, 회전,
재사용 시 family 폐기, JWT 원문 대신 hash/식별자 저장을 제안한다. 10/1 직접 본 refresh
API 페이지는 9/30 source/pending snapshot과 응답 예시·403 설명·추가 회원 수명 규칙이 다르다.
따라서 최신 캡처로 다시 맞추기 전에는 candidate 상태를 확정하지 않는다. OAuth candidate에만
있는 탈퇴 Member 재로그인 제한도 미정이다. Figma ERR-07은 로그인이 만료되면 로그인 화면으로 이동하고
“로그인이 만료됐어요. 다시 로그인해 주세요.” 주의 토스트를 표시한다고 적는다.
후보 흐름과 현재 코드의 차이는
[백엔드 로그인·API 정합 메모](../notion-api-alignment.md#인증로그인-2026-09-30-후보)에,
저장·동시성 제안과 미정 결정은
Persona 로그인 세션 draft(현재 저장소에 없는 과거 로컬 문서)에
기록했다. 로그인 Issue에 적힌 사용자 결정은 이번 기획 대조의 현재 지침으로 쓰되, 팀 승인과
Notion의 서로 다른 상태 표기는 구분한다.

부담, 녹음→전사→AI→노션 수작업, 긴 문서의 낮은 가독성, 최신 결정 혼선이 반복됐다.
9/29 이후에는 실제 팀으로 P0 녹음 습관, P1 정리 수고, P2 주제별 찾기, P3 읽기 부담을
검증한다. 이는 진행 중인 검증 계획이지 통과 결과나 팀 승인 요구사항이 아니다.

CareerForm 인터뷰에는 문서가 지나치게 잘게 나뉘면 복잡해지고 상위 도메인·트리 구조가
필요할 수 있다는 의견, 원문 전체 복사·문서 탭·문서/요약/녹음 이력 통합 요청이 있다.
Harudeul 메모에는 Codex CLI 연결과 기기 소음의 불편이 있다. Rilog·DFGG·외부팀 템플릿에는
완료된 답변이 없어 추가 제품 신호를 만들지 않는다. 상위 `인터뷰` 페이지에는 하위 DB가
있지만 해당 child record가 source snapshot에 빠져 있어 이 부모 후보는 미완료로 둔다.
개별 인터뷰 내용은 복제하지 않고, 이 요약도 현재 V2 정책이나 팀 승인으로 보지 않는다.

### #374 구현 중 확인한 담당자 결정과 후속 Issue

다음은 2026-09-29 #374 작업 대화에서 확인한 녹음 담당자의 지시다.
팀 Notion에 반영됐거나 팀 리뷰가 승인했다는 의미는 아니다.

- 연결 끊김은 이전 대화의 30초 heartbeat·2분 유예를 확정 기준으로 옮기지 않고,
  원문의 즉시 종료와의 충돌을 남겨 녹음 구현 전에 확정한다.
- 같은 멤버의 다른 탭·기기는 상태와 경과 시간을 보고 종료할 수 있다.
  새 녹음은 막고, 오디오 수집과 일시정지는 처음 녹음을 시작한 탭이 맡는다.
  이는 다른 멤버의 공동 녹음 참여와 별개다.
- 녹음 탭을 새로고침·닫을 때 브라우저 기본 나가기 확인을 거쳐 나가면 종료 신호를
  보내고 거기까지 문서로 정리한다. 다시 들어오면 문서 정리 중 상태이며 이어 녹음은
  이후 버전이다. 종료 신호가 전달되지 않은 경우의 처리 시점은 연결 끊김 결정과 함께 확인한다.

이 결정의 후속 녹음 Issue를 등록하면 해당 링크와 원문 동기화 상태를 갱신한다.

이후 2026-10-01 기준 #384/#385는 30초 heartbeat와 2분 만료를 구현 작업으로 명시하고,
#386은 무신호 2분 뒤 수집 중단을 후속 상태 전달 계약에 포함했다. 이 열린 Issue들의 최신
범위를 추적하되, Notion·ERD 문구나 구현이 동기화됐다고 간주하지 않는다.

### #378 구현에서 적용하는 후속 녹음 계약

2026-10-01 확인한 [녹음 시작 Issue #378](https://github.com/woowacourse-teams/2026-Knot/issues/378)과
담당자 인터뷰 결과가 위 #374 당시의 새로고침 종료 정책을 대체한다.
최초 탭은 같은 세션을 자동 복구하고 일시정지 상태를 유지한다. 오디오 수집 공백은 허용한다.
최초 탭의 신호 간격은 30초, 2분 무응답이면 종료한다. 명시적 종료는 즉시 처리하며,
닫기와 새로고침 구분·이탈 신호 실패는 유예 만료로 회수한다.

[시작 API 구현 계약](https://github.com/woowacourse-teams/2026-knot/blob/45d6b99993222ea4953b6f498294d8533b17fc6e/backend/docs/api/recording-start.md)은 멱등 키와 탭 증명을 구체화한다.
종료·복구·만료·오디오 후속 처리는 #381·#384·#385 등 후속 Issue에서 완성한다.
9월 30일 로컬 사본은 청크 대신 최종 파일 업로드와 `200 ENDED`인 세션 종료를 사용한다.
세션 종료만으로 문서 처리 중 상태를 반환하지 않는다. 팀 Notion 실시간 동기화는 미확인이다.

일반 탈퇴·OWNER 승계 탈퇴는 즉시 처리하고 본인의 진행 중·일시정지 녹음을 저장 없이 폐기한다.
다른 멤버 녹음과 이미 정상 종료·저장된 자료는 보존한다.
마지막 멤버(혼자 남은 OWNER) 탈퇴로 Workspace가 삭제되면 해당 Workspace의 진행 중 녹음을 모두 폐기한다.
권한 변경과 폐기 의도는 한 DB 트랜잭션으로 처리하고, 외부 임시 객체 정리는 커밋 뒤 재시도한다.
이는 #381·#386·#397·#409·#410의 담당자 확정 계약이며 #378의 구현 완료 범위는 아니다.

### 2026-10-09 녹음 연결 만료 판정 (#384)

2026-10-08 BE 이슈 계획의 담당자 결정에 따라 #384 범위를 바꿨다. 위 #378 절의 "최초 탭은 같은 세션을 자동 복구"는 이번 BE 범위에서 뺀다.
팀 Notion에 반영됐거나 팀 리뷰가 승인했다는 의미는 아니다.

- 최초 탭은 30초마다 신호를 보내고, 서버는 마지막 유효 신호 + 120초가 지나면 `CONNECTION_EXPIRED`로 종료한다.
  종료 시각은 판정한 시각이 아니라 마지막 신호 + 120초다.
- 신호·제어·시작 요청이 같은 판정을 먼저 하므로 늦은 요청은 끊긴 녹음을 되살리지 않는다.
- 브라우저 음성 보존과 이탈 시 수집 중지는 FE가 맡는다. 계약은 [녹음 생존 신호 API](https://github.com/woowacourse-teams/2026-knot/blob/45d6b99993222ea4953b6f498294d8533b17fc6e/backend/docs/api/recording-heartbeat.md)에 있다.

### 2026-10-15 녹음 연결 끊김 기준 변경 (#695)

팀 회의에서 탭을 닫은 녹음을 2분이 아니라 30초 안에 끝내기로 정했다([FE #694](https://github.com/woowacourse-teams/2026-Knot/issues/694)).
위 절들의 30초 신호·2분(120초) 만료를 대체한다. 팀 Notion 반영은 아직이다.

- 최초 탭은 10초마다 신호를 보내고, 서버는 마지막 유효 신호 + 30초가 지나면 `CONNECTION_EXPIRED`로 종료한다. 종료 시각은 마지막 신호 + 30초다.
- FE #694의 10초 주기를 먼저 배포한 뒤 BE 기준을 바꾼다. 결정 기록은 [ADR 695](../adr/695-recording-connection-timeout-30-seconds.md)다.

## 계속 적용할 기존 규칙

V2 전환은 모든 기술 규칙과 ADR의 일괄 폐기가 아니다.

- [기여 가이드](../../../CONTRIBUTING.md), [GitHub 컨벤션](../../../.github/knot-conventions.yml),
  기존 Issue·PR 템플릿과 [Issue·ADR 하네스](../../../docs/harness/issue-planning.md)는 계속 적용한다.
- 인증·초대·워크스페이스 계약은 관련 [ADR 목록](../adr/README.md), 연결 Issue,
  실제 API·테스트를 확인한다. 새 기획에 없다는 이유만으로 기존 계약을 제거하지 않는다.
  명시적 충돌이 발견되면 영향과 대체 결정을 해당 작업에서 다룬다.
- 백엔드의 팀 컨벤션은 [백엔드 컨벤션 원문][백엔드]의 00~08 개별 문서를 읽는다.
  V2 제품 범위와 언어·계층·테스트·API 작성 규칙은 별도로 판정한다.
- 과거 Notion 수집·검색 ADR은 당시 결정의 이력으로 보존한다. V2 요구사항으로
  자동 재사용하지 않는다. 실제 설계를 대체할 때 [ADR 생명주기](../adr/README.md)에
  따라 새 결정과 대체 관계를 남긴다.

## 2026-10-07 문서 생성 재시도 리뷰 반영 (이부분 수정됨)

사용자가 [PR #512](https://github.com/woowacourse-teams/2026-Knot/pull/512)의 두 리뷰를 모두 반영하도록 결정했다.
이 결정은 #494의 Workspace 멤버 전체 재시도와 별도 실행 접수 테이블 설계를 대체한다.

- 현재 Workspace 멤버이며 원본 녹음을 시작한 본인만 재시도할 수 있다.
  녹음의 `validateControlledBy` 규칙을 재사용하며 다른 멤버에게는
  `403 RECORDING_CONTROL_DENIED`를 반환한다. 거절은 Job 상태·횟수를 변경하지 않는다.
- 재시도 접수는 같은 Job의 QUEUED 상태·전체/사용자 횟수를 한 트랜잭션으로 저장한다.
  별도 실행 접수 Entity·Repository·미병합 V31은 제거한다. 실제 소비·실행·복구·정리
  설계와 필요 저장 구조는 #501에서 함께 결정한다.
- #494만으로 실제 FAILED Job이 생성되거나 AI 재생성이 시작되는 것은 아니다.
  현재 Job 생성·실패 기록 및 실행 소비 연결은 #501 범위로 남아 있다.
- 문서 목록·상세·연결 원문 읽기 권한에 녹음 소유자 제한을 확대하지 않는다.

근거는 사용자 리뷰 반영 지시, PR #512와 기존 RecordingSession 제어 규칙이다.
로컬 구현·테스트는 팀 원문 동기화·원격 PR 반영·운영 배포와 구분한다.

## 2026-10-08 녹음 종료를 최초 탭으로 제한

녹음 담당자가 사용자 직접 종료를 최초 녹음 탭에만 허용하도록 결정했다.
이 결정은 #374 당시의 "같은 멤버의 다른 탭·기기도 종료할 수 있다"와 #381의 종료 권한을 대체한다.
팀 Notion에 반영됐거나 팀 리뷰가 승인했다는 의미는 아니다.

- 종료 요청은 일시정지·재개와 같은 `{tabId, controlToken}` 증명을 보내야 한다.
  계약은 [녹음 종료 API](https://github.com/woowacourse-teams/2026-knot/blob/45d6b99993222ea4953b6f498294d8533b17fc6e/backend/docs/api/recording-end.md)에 있다.
- 다른 탭과 틀린 증명은 `403 RECORDING_CONTROL_DENIED`다. 이미 종료된 녹음의 재요청도 증명을 먼저 확인한다.
- 본문 없는 기존 호출과 호환되는 경로는 두지 않는다. 2026-10-09 결정에 따라 이 변경을 먼저 배포하고,
  FE가 종료 호출을 고쳐 배포할 때까지 개발 서버의 종료가 실패하는 공백은 감수한다.
- 서버 자동 종료(연결 만료·2시간 상한)는 이 제한과 별개이며 #384·#385에서 다룬다.

근거는 #530과 2026-10-08 녹음 담당자의 결정이다.
[ADR 378](../adr/378-recording-tab-recovery-and-expiry.md)은 기존 Proposed 기록으로 수정하지 않았다.

## 2026-10-12 탐색 첫 답변 재시도 중지의 목록 노출

[PR #612 리뷰](https://github.com/woowacourse-teams/2026-knot/pull/612#discussion_r4244108426)에 대한 사용자 결정이다.
첫 답변 실패로 숨겨진 대화는 재시도 중에도 숨김을 유지하고, COMPLETED 또는 STOPPED로 끝나면 목록에 복원한다.
출력 전 중지로 본문이 비어 있어도 STOPPED는 목록에 표시한다. 재시도 실패는 계속 숨긴다.
중지한 부분 답변은 보존하며 이후 질문 문맥에 포함한다. STOPPED 답변은 실패 재시도 대상이 아니다.
이 결정은 #569의 “성공하면 목록 노출 복원”에서 명시하지 않았던 사용자 중지의 처리를 확정한다.
운영 Notion 원문 동기화와 팀 리뷰 승인·운영 배포를 의미하지 않는다.

## 2026-10-14 #670 생성 완료 DRAFT 문서 탐색

[#670](https://github.com/woowacourse-teams/2026-knot/issues/670)의 사용자 결정으로 기존 ARCHIVED 전용 탐색 범위를 변경한다.

Transcript·오디오·생성 중/실패 Job은 직접 검색하지 않는다. DB 직접 조회 방식의 제외 수 0과

### 약관 동의 정책과 API 제안의 적용 경계

10월 20일 08:08 UTC 수정된 [약관 동의 (v2)](https://www.notion.so/3ffb435175228103bc4cf1bbd0bf0a7d)는
원문에서 정책 정본으로 지정됐다. 가입 시 이용약관·만 14세 확인을 받고 개인정보 처리방침은
안내하며, 기존 회원의 첫 동의와 중요한 변경 후 재동의를 구분한다.
[변경 로그](https://www.notion.so/3deb4351752281a99829f339cc9ceeb4)(08:13 UTC)는
같은 날의 서버 본문 저장안을 명시적으로 대체한다. 본문·이전 버전·공지 정보는 FE에 함께
배포하고, 서버는 요구 버전 설정과 동의 이력으로 동의 필요 여부를 판단하는 최소안이다.
공개 본문 조회 API와 약관 전용 불러오기 실패 화면은 이 안에서 제외됐다.
이 정책 표기와 실제 구현 완료는 구분한다.

별도 BE 전달용 요청은 원문 변경 로그에서 휴지통 이동으로 명시됐고, 제안은 (신)API 명세서로 옮겨졌다.
[동의 저장 API 초안](https://www.notion.so/3ffb4351752281b887c4e1d8f6d95fd6)(08:11 UTC)의
method 속성은 `POST`, 경로는 `/api/v1/members/me/terms-agreements`이며 구현 속성은 NO다.
[닉네임 요청](https://www.notion.so/3ebb43517522802fb8a1e43c6234d470)과
[회원 정보](https://www.notion.so/3ffb43517522817f9a48c2954672b5ae)(각 08:07 UTC)는
현재 구현과 추가 초안을 별도 절로 구분한다. 추가 제안은 가입 요청의 `termsVersion`·
`ageOver14Confirmed`, 회원 정보의 `termsAgreementRequired`·`ageConfirmationRequired`다.
직전 `requiredConsents`·문서 version ID·`legal-agreements` 제안 및 과거 `agreedTermsVersion`
계약과 섞어 사용하지 않는다. 세 API 모두 추가 계약은 **BE 구현 후 확정할 초안**이다.

현재 checkout의 `CompleteNicknameRequest`는 nickname만 받고, `AuthenticatedMemberResponse`와
`Member`에는 동의 필드가 없다. 관련 [FE #860](https://github.com/woowacourse-teams/2026-Knot/issues/860)·
[#861](https://github.com/woowacourse-teams/2026-Knot/issues/861)은 조회 당시 OPEN이며,
#861은 Proposed ADR 예정 경로를 적고 있다. 해당 ADR 파일은 현재 checkout에서 확인하지 못했다.
BE 계약을 확정하고 FE 요청·응답 및 해당 ADR과 다시 대조해야 한다.

탈퇴 후 동의 기록 보관 기간은 원문의 1년 제안과 3년 대안 사이에서 확인 대기다.
로그인 고지 문구와 명시적 동의의 정합성 및 오류 코드·응답 등 BE 계약 확정은 남아 있다.
원문에서 이전 버전 주소는 시행일로, 사소한 변경 후 기록 버전은 그대로 두는 것으로 정리됐다.
중요한 변경일에는 BE 요구 버전 배포 후 FE 본문을 바로 배포하며 그 사이의 409를 새로 고침
안내로 처리하는 틈을 허용한다고 명시한다. 최초 도입의 BE→FE→BE 단계 배포 제안은
기존 가입 요청을 막지 않기 위한 것이다. 이 원문 정리와 실제 승인·배포 관측은 구분한다.
