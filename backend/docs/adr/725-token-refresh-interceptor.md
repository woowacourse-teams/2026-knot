# 401을 받으면 httpClient 응답 인터셉터에서 토큰을 재발급하고 원래 요청을 한 번 다시 보낸다

## 상태

Proposed

## 관련 Issue

- #725 [FE] 401을 받으면 토큰을 재발급해 로그인을 이어 가기

## 한 줄 요약

401을 받으면 httpClient 응답 인터셉터에서 토큰을 재발급하고 원래 요청을 한 번 다시 보낸다

## 왜 이 결정이 필요했나

접근 토큰은 1시간 뒤 만료되고, 백엔드는 refresh 토큰을 회전하며 이미 쓴 토큰이 다시 오면 세션을 끊는다. #551은 처리 위치를 httpClient 인터셉터와 QueryCache · MutationCache onError 중에서 고르고 이유를 남기라고 적었다.

2026-10-16 이스타가 로그인 1시간 뒤 401로 로그인 화면에 가는 문제를 #551보다 먼저 고치기로 했다.

결정 동인:

- 원래 요청을 사용자 모르게 다시 보낼 수 있어야 한다
- Query 밖의 요청과 뮤테이션도 같은 규칙을 따라야 한다
- 같은 refresh 토큰으로 재발급이 동시에 나가지 않게 한 곳에서 막아야 한다

## 트레이드 오프

- httpClient 응답 인터셉터: 모든 axios 요청을 한 곳에서 재발급하고 다시 보낸다. axios 밖의 요청(SSE fetch)은 따로 다뤄야 한다
- QueryCache · MutationCache onError: Query 단위로 실패를 알 수 있지만 원래 요청을 그대로 다시 보낼 수 없고, Query 밖의 요청을 잡지 못한다

## 무엇을 결정했나

401을 받으면 httpClient 응답 인터셉터에서 토큰을 재발급하고 원래 요청을 한 번 다시 보낸다

원래 요청을 다시 보낼 수 있는 곳은 요청 계층뿐이고, 재발급을 한 번씩만 실행하는 잠금도 한 곳에 있어야 한다.

## 결과

- axios 요청이 401을 받으면, 재발급에 성공했거나 다른 요청이 이미 재발급을 끝낸 경우에만 원래 요청을 한 번 다시 보낸다(재발급 · CSRF 경로는 제외)
- Web Locks가 없는 브라우저에서는 잠금 없이 진행해, 탭 사이에서 같은 refresh 토큰으로 재발급이 겹칠 수 있다
- SSE 요청은 이 인터셉터를 거치지 않아 따로 다뤄야 한다
- #551의 전역 401 처리는 이 인터셉터가 원래 401을 던진 뒤에 붙는다

## 다시 논의해야 할 조건

- #551에서 전역 401 처리를 붙일 때
- SSE 요청에도 재발급이 필요해질 때
- 백엔드가 재발급 방식(회전 · 재사용 감지)을 바꿀 때

### 후속 근거 대조 · 2026-10-18

- [AUTH-QA-015 원문](https://www.notion.so/3f9b4351752281a0abbccf13be878244)의 수정 시각은 2026-10-17 17:13 UTC다. DB 속성에는 개발 서버에서 10월 18일 01:42 KST에 `me 401 → CSRF 조회 200 → refresh 204 → me 200`을 확인했고 홈을 유지해 `Pass`로 판정했다고 기록되어 있다. 이는 팀의 QA 기록이며 이번 문서 동기화에서 브라우저 흐름을 재현한 결과가 아니다. BE 배포 커밋은 해당 기록에서도 확인하지 못했다.
- 같은 관측에서 초대 카드가 비는 문제는 [#785](https://github.com/woowacourse-teams/2026-knot/issues/785)로 분리됐다. 2026-10-18 조회 시 열린 Issue이며, 동시 변경 요청의 CSRF 토큰 조회를 공유하고 제한된 재시도를 추가하는 작업이다. 로그인 연장 QA의 Pass를 동시 변경 요청까지 검증한 결과로 확대하지 않는다.
- 로컬 코드에는 `refreshInterceptor`의 진행 중 재발급 공유와 Web Locks가 있고, `csrfInterceptor`는 CSRF 조회의 진행 중 Promise를 공유하지 않고 403 뒤 한 번 다시 보낸다. `AuthController.refresh`는 재발급과 새 쿠키 발급 경로를 제공한다. 이는 로컬 구현 관측이며 개발 서버의 배포 버전 증거는 아니다.
- [재발급 API 원문](https://www.notion.so/3ebb4351752280a5ba6af3743703998b)의 회전·CSRF·204 계약을 유지한다. 원문의 `미구현` 메모는 현재 로컬 코드 및 위 QA 기록과 다르므로 현재 구현 상태의 근거로 채택하지 않는다. 이 대조는 ADR의 Proposed 상태나 팀 승인 여부를 변경하지 않는다.
