# 새 소식 노트는 모든 main 머지에서 GitHub Actions의 Claude Code가 써서 Notion DB에 바로 게시하고, 앱은 프론트 Worker가 요청 때 읽은 Notion DB에서 받는다

## 상태

Proposed

## 관련 Issue

- #956 [FE] main 머지 때 Claude가 새 소식을 써서 Notion에서 보여 주기

## 한 줄 요약

새 소식 노트는 모든 main 머지에서 GitHub Actions의 Claude Code가 써서 Notion DB에 바로 게시하고, 앱은 프론트 Worker가 요청 때 읽은 Notion DB에서 받는다

## 왜 이 결정이 필요했나

ADR 911은 노트를 기획자가 릴리즈 직전에 프론트 상수 파일에 쓰기로 했고, 서버나 노션에서 받아 오는 안은 브라우저에 노션 토큰을 둘 수 없어 BE API가 필요하다는 이유로 뺐다. 서버는 바꾸지 않는다는 조건은 그대로다. 프론트에는 이미 `/relay` 아래 요청을 받는 Cloudflare Worker가 있고(ADR 838), 피드백을 Notion에 넣는 데 쓰고 있다(ADR 930)

v0.4.0(반응형 화면)과 v0.5.0(피드백 보내기)은 사용자에게 보이는 기능이 나갔지만 새 소식 노트 없이 배포됐고, 상수 파일 맨 위는 아직 v0.2.0이다. 기획자가 릴리즈마다 노트 PR을 먼저 머지하는 방식이 지켜지지 않았다.

결정 동인:

- 서버(BE)를 바꾸지 않는가
- 브라우저에 토큰을 두지 않는가
- 다시 배포하지 않고 문구를 고칠 수 있는가
- 사람이 잊어도 노트가 빠지지 않는가
- Anthropic 약관 안에서 Claude를 실행하는가

## 트레이드 오프

- 읽는 곳, 상수 파일 유지(ADR 911): 배포와 함께 나가고 CI로 확인할 수 있지만 사람이 쓰지 않으면 빠지고 고치려면 배포가 필요하다
- 읽는 곳, 배포 때 Notion에서 가져와 빌드에 넣기: 토큰이 빌드에만 있지만 문구를 고칠 때마다 다시 배포해야 한다
- 읽는 곳, 서버가 Notion 읽기: 서버를 바꿔야 해서 뺐다
- 읽는 곳, Worker가 요청 때 Notion 읽기(채택): 서버 변경과 브라우저 토큰 없이 배포 없이 고칠 수 있지만 Notion 장애와 캐시 지연을 받아들인다
- 쓰는 이, 기획자 직접: 문구 품질은 높지만 v0.4.0과 v0.5.0처럼 빠진다
- 쓰는 이, Worker 안에서 setup-token으로 Claude 실행: Worker에서는 Claude Code를 실행할 수 없고 구독 토큰을 직접 쓰는 것은 약관에 어긋나 뺐다
- 쓰는 이, Actions에서 Claude Code 실행(채택): 공식 지원 방식이고 Claude 앱 설치 없이 Actions 기본 토큰으로 된다
- 게시, 사람 확인 뒤: 잘못된 노트를 막지만 확인을 잊으면 다시 빠진다
- 게시, 바로(채택): 빠지지 않지만 잘못 쓴 노트가 고치기 전까지 보인다

## 무엇을 결정했나

새 소식 노트는 모든 main 머지에서 GitHub Actions의 Claude Code가 써서 Notion DB에 바로 게시하고, 앱은 프론트 Worker가 요청 때 읽은 Notion DB에서 받는다

Worker는 이미 Notion 토큰을 비밀값으로 두고 중계하고 있어 서버 변경 없이 읽을 수 있다. Claude Code는 Actions에서만 공식으로 실행할 수 있다. 노트가 빠진 원인이 사람의 작성과 확인 단계라 모든 main 머지에서 자동으로 바로 게시한다

## 결과

- 좋은 점: 사람이 잊어도 사용자 변화가 있는 머지마다 노트가 생긴다
- 좋은 점: Notion에서 고치면 다시 배포하지 않아도 반영된다
- 좋은 점: 서버와 브라우저에 새 토큰이 없다
- 나쁜 점: Claude가 잘못 쓴 노트가 도넛이 고치기 전까지 보인다
- 나쁜 점: 도넛 개인 Claude 구독과 setup-token(1년)에 기대고, Notion 장애 때 패널이 빈다
- ADR 911을 대체하고 #917은 필요 없어진다

## 다시 논의해야 할 조건

- 잘못 게시된 노트가 반복될 때
- setup-token을 쓸 사람이 없거나 구독 한도로 노트가 자주 빠질 때
- 사용자마다 다른 소식을 보여 줘야 할 때
- 서버를 바꿀 수 있게 될 때
