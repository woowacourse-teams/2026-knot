# 상대 날짜와 모델의 requestedAt은 최초 질문 접수, 문서 생성 상한은 현재 요청 영수증 접수, 실행 만료는 워커 시작을 사용한다.

## 상태

Proposed

## 관련 Issue

- #1085 [BE] 탐색 질문의 날짜 기준과 재시도 시점 구분

## 한 줄 요약

상대 날짜와 모델의 requestedAt은 최초 질문 접수, 문서 생성 상한은 현재 요청 영수증 접수, 실행 만료는 워커 시작을 사용한다.

## 왜 이 결정이 필요했나

탐색 재시도는 같은 질문과 답변 ID를 재사용하고 새로운 접수 영수증을 저장한다.

워커 시작으로 상대 날짜와 문서 생성 상한을 정해 자정 이후 다른 회의를 인용하고 접수 뒤 자료를 포함했다.

결정 동인:

- KST 자정에서 상대 날짜 일관성
- 질문 접수와 워커 지연의 독립
- 기존 저장 데이터 재사용

## 트레이드 오프

- 기존 실행 시작 시각을 날짜 해석과 문서 상한에 공통으로 사용한다. 값 하나로 단순하지만 자정 경계 및 대기 중 문서 범위 오류가 재현됐다.
- 최초 USER 메시지와 현재 요청 영수증의 접수 시각을 사용하고 워커 시각은 실행 만료에 사용한다. 중복 접수의 기존 영수증을 그대로 재사용한다.

## 무엇을 결정했나

상대 날짜와 모델의 requestedAt은 최초 질문 접수, 문서 생성 상한은 현재 요청 영수증 접수, 실행 만료는 워커 시작을 사용한다.

USER 메시지와 요청 영수증에 필요한 값이 이미 저장된다. 현재 실행 잠금과 기존 권한 검사를 활용할 수 있다.

## 결과

- 실행 claim 시 기존 요청 영수증을 조회한다.
- 접수 영수증이 없는 이전 답변은 질문 접수 시각을 사용한다.

## 다시 논의해야 할 조건

- 새 재시도 실행 모델이 접수 영수증의 순서 또는 결합 관계를 바꿀 때
