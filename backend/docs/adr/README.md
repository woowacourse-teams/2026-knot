# Architecture Decision Records

ADR은 여러 대안을 검토한 결정 중 제품 정책, 아키텍처, 보안, 데이터 또는 공용
워크플로우에 장기간 영향을 주는 결정을 기록한다.

## 생명주기

1. Issue 기획에서 실제 대안, 장기 영향과 반복 참조 여부로 ADR 필요성을 판단한다.
2. AI는 현재 상황, 결정 필요성, 실제로 논의한 대안과 선택 이유의 근거를 확인한다.
   근거가 부족하거나 충돌하거나 현재 유효성이 불명확할 때만 인터뷰한다. 대안이 없으면
   없다고 기록하며 새 대안을 만들지 않는다.
3. Issue의 `메모`에는 결정 한 줄과 예정 경로만 기록한다. 새 Issue 번호가 정해지기 전에는
   `backend/docs/adr/{ISSUE_NUMBER}-<slug>.md`로 표시한다. ADR 전문과 인터뷰 원문은 넣지 않는다.
4. Issue 단계에서는 ADR 파일을 만들지 않는다.
5. 실제 Issue 번호를 확인한 뒤 구현 브랜치에서 AI가
   `backend/docs/adr/<Issue 번호>-<slug>.md`를 `Proposed`로 만들고 코드와 같은 PR에 포함한다.
6. 팀이 PR에서 결정을 승인한 뒤에만 상태를 `Accepted`로 바꾼다. AI는 자동 merge하지
   않는다.
7. 결정을 대체하면 기존 ADR을 보존하고 새 ADR에서 `Superseded` 관계를 기록한다.

## 필수 항목

```markdown
# 결정 제목

## 상태

Proposed

## 관련 Issue

- #123

## 한 줄 요약

한 줄 요약

## 왜 이 결정이 필요했나

현재 맥락, 구체적인 문제 상황과 결정 동인

## 트레이드 오프

실제로 논의한 선택지, 장점, 단점과 채택 여부

## 무엇을 결정했나

채택한 결정과 선택 이유

## 결과

긍정적·부정적 결과와 운영 영향

## 다시 논의해야 할 조건

## 확인

결정 확인 주체와 방법
```

이 형식은 MADR의 핵심 요소를 팀 Notion ADR 템플릿에 맞게 줄인 형태다. 대화 전문, AI가
제안했지만 논의하지 않은 대안, 계정 정보, 시크릿과 개인정보를 기록하지 않는다.

파일명에는 실제 GitHub Issue 번호를 선행 0 없이 사용한다. 현재 생명주기 결정은
[ADR #167](167-short-issue-and-proposed-adr-lifecycle.md)에서 확인한다.
