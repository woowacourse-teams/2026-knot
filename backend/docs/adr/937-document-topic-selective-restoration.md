# 직전 재정리의 변경 문서만 복원하고 이후 문서는 유지한다.

## 상태

Proposed

## 관련 Issue

- #937 [BE] 직전 주제 정리 되돌리기 시작 API 구현

## 한 줄 요약

직전 재정리의 변경 문서만 복원하고 이후 문서는 유지한다.

## 왜 이 결정이 필요했나

전체 분류 체계를 원복하면 재정리 이후 문서의 배정까지 바뀌거나 참조 주제가 사라질 수 있다.

사용자는 새 문서까지 이전 체계로 다시 배정하는 안과 재정리했던 기존 문서만 복원하는 안을 비교한 뒤 후자를 선택했다.

결정 동인:

- 새 문서의 배정과 참조를 보존한다.
- 내용·확인 상태와 원래 안건을 유지한다.
- 실패 시 복원 기회를 소진하지 않는다.

## 트레이드 오프

- 새 문서까지 이전 체계로 재배정: 전체 체계는 되돌리지만 새 문서 추가 분류와 처리 시간이 필요하다.
- 직전 재정리의 변경 문서만 복원: 이후 문서는 유지되지만 과거 체계와 후속 주제가 함께 남을 수 있다.

## 무엇을 결정했나

직전 재정리의 변경 문서만 복원하고 이후 문서는 유지한다.

사용자가 재정리 대상의 선택적 복원을 확정했고 새 문서 배정 유지가 요구사항이다. 저장된 이전 배정으로 복원하여 LLM 재분류를 하지 않는다.

## 결과

- 원본 changed 집합과 복원 작업별 expected/restored 배정을 저장한다.
- 공통 Workspace 잠금과 APPLYING 토큰으로 배정·주제 상태·성공·소진을 원자화한다.
- 직전 복원본 한 건과 requestId 기록의 보존을 분리한다.
- LEGACY·FALLBACK와 원래 provenance를 복원하고 주제를 물리 삭제하지 않는다.

## 다시 논의해야 할 조건

- 주제 이름·설명 수정 기능을 추가할 때
- 여러 과거 버전 선택이나 새 문서까지 원복하는 기능이 요구될 때
