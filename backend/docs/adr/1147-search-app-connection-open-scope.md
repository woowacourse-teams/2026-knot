# 앱 연결(첫 앱은 노션)은 접근 범위를 좁히지 않고, 멤버 누구나 연결하며 연결한 사람이 볼 수 있는 전부를 워크스페이스 멤버 모두가 탐색에서 읽고 쓴다

## 상태

Proposed

## 관련 Issue

- #1147 [BE] 탐색에서 연결한 노션을 읽고 확인 카드로 페이지 만들기

## 한 줄 요약

앱 연결(첫 앱은 노션)은 접근 범위를 좁히지 않고, 멤버 누구나 연결하며 연결한 사람이 볼 수 있는 전부를 워크스페이스 멤버 모두가 탐색에서 읽고 쓴다

## 왜 이 결정이 필요했나

탐색에 연결한 앱(첫 앱은 노션)을 읽고 쓰는 기능을 더하면서 연결 방식과 읽고 쓰는 범위, 누가 연결하는지, 노션에서 그 페이지를 볼 수 없는 멤버에게도 내용이 보이는지를 정해야 했다.

2026-11-11과 2026-11-12에 설계 노션 「탐색 AI 앱 연결 설계」의 「노션 연결」에서 노션 일반 API(공개 통합 OAuth)와 노션 MCP를 비교했다. 일반 API 검색이 제목으로만 찾는다는 것은 2026-11-11 팀 노션 호출로, 노션 MCP 검색이 본문까지 찾는다는 것은 2026-11-12 호출로 확인했다. 결정은 2026-11-13 기능 제안의 1차 컨펌을 거쳐 기능 요구사항 SEARCH-R29~R54에 들어갔다.

결정 동인:

- 노션 페이지를 이름뿐 아니라 내용으로 찾아야 한다(2026-11-12 결정).
- 노션 내용은 미리 저장하거나 색인하지 않고 질문할 때마다 가져온다.
- 노션에서 그 페이지를 볼 수 없는 멤버에게도 내용이 보여도 된다는 결정(2026-11-11, 2026-11-12)은 연결하는 사람의 동의를 조건으로 한다.

## 트레이드 오프

- 노션 일반 API(공개 통합 OAuth): 연결할 때 페이지를 골라 보이는 범위가 좁혀지고 심사 없이 시작할 수 있다. 하지만 검색이 제목으로만 찾아서, 내용으로 찾으려면 고른 페이지를 Knot이 미리 색인해야 한다.
- 노션 MCP(고른 방식): 검색이 본문까지 찾고 서버가 토큰을 보관해 MCP 클라이언트로 붙는다. 하지만 페이지를 고르는 단계가 없어 연결한 사람이 노션에서 볼 수 있는 전부가 범위가 되고, 노션 게스트는 연결하지 못하며, 접근 토큰 8시간과 갱신 토큰 180일을 관리해야 한다.

## 무엇을 결정했나

앱 연결(첫 앱은 노션)은 접근 범위를 좁히지 않고, 멤버 누구나 연결하며 연결한 사람이 볼 수 있는 전부를 워크스페이스 멤버 모두가 탐색에서 읽고 쓴다

노션 MCP로 연결한다. 페이지를 고르는 단계가 없어 연결한 사람이 노션에서 볼 수 있는 내용 전부(개인 페이지 포함)가 읽고 쓰는 범위가 되고, 서버는 질문한 멤버가 노션에서 그 페이지를 볼 수 있는지 확인하지 않는다. 워크스페이스 멤버 누구나 연결할 수 있고, 끊기는 연결한 사람과 워크스페이스 소유자가 한다. 연결하는 사람은 「내가 노션에서 볼 수 있는 내용 전부가 이 워크스페이스 멤버 모두에게 보일 수 있다」는 안내에 동의해야 연결할 수 있다. 내용으로 찾기를 필수로 정했는데 일반 API로는 미리 색인이 필요해서 이 방식을 골랐다.

## 결과

- 노션 게스트는 연결하지 못한다(노션 MCP가 노션 워크스페이스 멤버만 허용한다).
- 노션 쓰기는 연결한 사람 권한으로 나가고, 질문한 멤버가 쓰기 확인 카드를 실행했을 때만 한다.
- Knot 서버는 노션 MCP 도구 가운데 정해 둔 검색, 내용 가져오기, 페이지 만들기, 연결 정보 조회만 부른다.
- 연결 토큰은 암호화해 저장하고, 끊거나 연결한 사람이 워크스페이스를 나가면 연결을 지운다.

## 다시 논의해야 할 조건

- 연결한 사람의 개인 페이지까지 멤버에게 보이는 범위를 줄여 달라는 요구가 생길 때
- 노션 일반 API 검색이 본문까지 찾게 될 때
- 노션 외 다른 앱을 연결할 때
