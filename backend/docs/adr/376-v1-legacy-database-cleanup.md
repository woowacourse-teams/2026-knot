# V1–V13 마이그레이션 이력을 보존하고 V14에서 인증·워크스페이스 기반 외의 V1 레거시 기능 스키마와 데이터를 삭제한다.

## 상태

Proposed

## 관련 Issue

- #376 [BE] V1 레거시 DB 스키마 정리

## 한 줄 요약

V1–V13 마이그레이션 이력을 보존하고 V14에서 인증·워크스페이스 기반 외의 V1 레거시 기능 스키마와 데이터를 삭제한다.

## 왜 이 결정이 필요했나

V1 기능 코드 제거 뒤 DB에는 더 이상 사용하지 않는 채팅·Notion 수집·검색 테이블과 vector 확장이 남는다.

코드 삭제 후 DB를 그대로 유지할지, 현행 기반을 제외한 레거시 스키마와 데이터를 제거할지 결정해야 한다.

결정 동인:

- 현재 코드가 필요로 하는 스키마만 남겨 바로 개발할 수 있게 한다.
- 이미 적용된 Flyway 이력을 바꾸지 않고 배포된 DB를 전진 마이그레이션한다.
- 회원·인증·워크스페이스 기반의 기존 사용자 데이터를 보존한다.
- 예상하지 못한 의존성을 마이그레이션 실패로 드러낸다.

## 트레이드 오프

- 레거시 스키마와 데이터를 그대로 보존: 복구 여지는 있지만 사용하지 않는 V1 구조가 개발 DB에 계속 남는다.
- DB를 새로 만들며 전체 스키마와 데이터를 비우기: 가장 깨끗한 시작이지만 유지 기능의 회원·인증·워크스페이스 데이터까지 없어진다.

## 무엇을 결정했나

V1–V13 마이그레이션 이력을 보존하고 V14에서 인증·워크스페이스 기반 외의 V1 레거시 기능 스키마와 데이터를 삭제한다.

과거 마이그레이션을 불변으로 두고 V14에서 구형 기능 종속 객체만 제거하면 배포 DB와 새 DB가 같은 최신 스키마에 도달하면서 유지 대상 기반은 보존된다.

## 결과

- V1 채팅·Notion 수집·검색 데이터는 V14 적용 시 삭제된다.
- 환경에는 V14 적용 전 백업과 V1 코드 제거 배포 순서가 필요하다.
- V13 재생 때문에 pgvector PostgreSQL 이미지는 유지한다.
- V2는 기존 V1 기능 스키마와 데이터를 물려받지 않고 새 스키마로 개발한다.

## 다시 논의해야 할 조건

- 유지 대상 기능이 제거 대상으로 분류된 테이블을 다시 필요로 할 때
- V1 데이터를 V2로 이전해야 한다는 요구사항이 생길 때
