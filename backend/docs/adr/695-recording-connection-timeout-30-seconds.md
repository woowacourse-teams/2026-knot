# 녹음 최초 탭은 10초마다 생존 신호를 보내고 서버는 마지막 유효 신호 뒤 30초가 지나면 녹음을 연결 만료로 끝낸다

## 상태

Proposed

- 30초 만료와 끝난 시각 계산은 ADR 1065가 마지막 생존 뒤 30분 유예와 끝난 시각 = 마지막 생존 시각으로 대체했다. 10초 신호 주기는 유지한다.

## 관련 Issue

- #695 [BE] 녹음 연결 끊김 기준을 30초로 줄이기

## 한 줄 요약

녹음 최초 탭은 10초마다 생존 신호를 보내고 서버는 마지막 유효 신호 뒤 30초가 지나면 녹음을 연결 만료로 끝낸다

## 왜 이 결정이 필요했나

ADR 378은 브라우저 이탈 신호를 믿지 않고 2분 무응답 만료로 닫힌 탭을 처리했다. 이때 닫기 종료 지연을 감수했다. 최초 탭의 생존 신호 주기는 #384(PR #544)에서 30초로 정했다.

탭을 닫은 녹음이 마지막 신호 뒤 2분 동안 진행 중으로 남는다. 팀 회의에서 이 지연을 30초로 줄이기로 정했다.

결정 동인:

- 탭을 닫은 녹음의 종료 지연 단축
- 30초 기준 안에 생존 신호가 닿도록 FE 주기 조정
- FE를 먼저 배포해 진행 중 녹음이 바로 끝나지 않게 함

## 트레이드 오프

- 현재 유지(30초 주기·2분 기준): 신호가 연속 두 번 실패해도 유지되지만 탭을 닫은 녹음이 2분 동안 남는다
- 10초 주기·30초 기준(채택): 닫힌 탭의 녹음을 30초 안에 끝내지만 신호가 연속 두 번 실패하면 끝나고 신호 요청이 3배가 된다

## 무엇을 결정했나

녹음 최초 탭은 10초마다 생존 신호를 보내고 서버는 마지막 유효 신호 뒤 30초가 지나면 녹음을 연결 만료로 끝낸다

팀 회의에서 탭을 닫은 녹음을 2분이 아니라 30초 안에 끝내기로 정했다. 30초 기준 안에 신호가 닿도록 주기를 10초로 줄이고 FE를 먼저 배포한다.

## 결과

- 닫힌 탭의 녹음이 마지막 신호 뒤 30초에 끝나고 종료 시각도 마지막 신호 + 30초다
- 신호가 연속 두 번 실패하거나 서버가 30초 가까이 응답하지 못하면 녹음이 끝난다
- 생존 신호 요청이 녹음당 분당 2회에서 6회로 는다
- Chrome이 오래 숨긴 탭의 타이머를 늦추는 경우를 감수한다
- Superseded 범위: ADR 378의 2분 무응답 종료. 최초 탭 제어 증명, 같은 탭 새로고침 복구, 다른 탭 조회·종료 규칙은 유지한다

## 다시 논의해야 할 조건

- 일시적 장애나 재배포로 녹음이 연결 만료로 끝나는 사례가 반복될 때
- 숨긴 탭의 타이머 지연으로 녹음이 끝나는 사례가 확인될 때
