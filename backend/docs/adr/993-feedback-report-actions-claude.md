# 피드백 접수함 요약은 GitHub Actions에서 매일 아침 도구를 끈 Claude Code(`claude -p`)가 기존 구독 setup-token으로 쓰고, 새 접수가 있을 때만 스크립트가 접수함 설명란 맨 위를 바꾼다

## 상태

Proposed

## 관련 Issue

- #993 [FE] 매일 아침 Claude가 최근 7일 피드백 요약을 접수함 설명란에 쓰기

## 한 줄 요약

피드백 접수함 요약은 GitHub Actions에서 매일 아침 도구를 끈 Claude Code(`claude -p`)가 기존 구독 setup-token으로 쓰고, 새 접수가 있을 때만 스크립트가 접수함 설명란 맨 위를 바꾼다

## 왜 이 결정이 필요했나

피드백 보내기(ADR 930)로 누구나 공개 경로 `/relay/f`를 거쳐 노션 접수함에 글을 넣을 수 있게 됐고, 2026-10-19~23에만 89건이 쌓였다. 팀은 서버(BE)를 바꾸지 않고 자동화하길 원하며, 새 소식 자동 작성(ADR 956)이 이미 Actions에서 구독 setup-token으로 Claude Code를 실행한다

피드백 접수함에 일주일 만에 89건이 쌓였는데, 팀 우선순위와 크리티컬 문제를 뽑으려면 누군가 계속 전부 읽어야 합니다. 접수함은 페이지 전체가 DB라 DB 위에 요약 블록을 둘 수도 없습니다.

결정 동인:

- 팀이 함께 관리할 수 있는가
- 상시 서버 없이 도는가
- 팀이 이미 쓰는 Claude 호출 방식을 따르는가
- 새 비용과 키 발급 없이 시작할 수 있는가
- 공개 접수함의 글이 Claude에게 권한을 주지 않는가

## 트레이드 오프

- 실행, 노션 커스텀 에이전트: 코드가 필요 없지만 Business 이상 요금제와 워크스페이스 관리자 권한이 필요하고 게스트라 요금제를 확인하지 못했다
- 실행, knotted 개인 서버 cron: 기존 cron과 Agent SDK에 붙이면 되지만 개인 서버라 팀원이 관리하기 어렵다
- 실행, 내부 자동화 전용 Cloudflare Worker: 팀 Worker 배포 방식을 쓰고 Cron Triggers가 있지만 Claude Code와 Agent SDK를 실행할 수 없어 Messages API를 직접 불러야 하고 키도 따로 둬야 한다
- 실행, Managed Agents: 정기 실행과 샌드박스를 Anthropic이 맡지만 베타이고 API 키로 과금되며 팀의 `claude -p` 방식과 다르다
- 실행, GitHub Actions 예약 실행(채택): 서버 없이 팀 저장소에서 관리하고 러너에서 Claude Code를 그대로 실행한다
- 인증, Console API 키: 약관 걱정이 없지만 키 발급, 월 한도, 비용 부담 합의가 필요하다
- 인증, 기존 구독 setup-token(채택): 이미 등록된 시크릿이라 바로 쓸 수 있지만 도넛 구독에 기댄다
- 위치, 별도 리포트 페이지: 제목과 토글 같은 서식을 쓸 수 있지만 접수함과 따로 열어야 한다
- 위치, 접수함 DB 설명란 맨 위(채택): 접수함을 열면 바로 보이지만 서식이 없고 안내 문구를 구분선 아래로 옮겨야 한다

## 무엇을 결정했나

피드백 접수함 요약은 GitHub Actions에서 매일 아침 도구를 끈 Claude Code(`claude -p`)가 기존 구독 setup-token으로 쓰고, 새 접수가 있을 때만 스크립트가 접수함 설명란 맨 위를 바꾼다

하루 한 번 도는 배치 작업이라 상시 서버가 필요 없고, Actions 러너에서는 팀이 FE 스크립트와 ADR 956에서 쓰는 Claude Code를 그대로 실행할 수 있다. 이미 등록된 구독 setup-token을 쓰면 새 키와 비용 합의 없이 시작하고, 새 접수가 없는 날은 Claude를 부르지 않아 사용량도 줄인다. 접수함이 full-page DB라 블록을 넣을 수 없어 설명란을 쓴다. 공개 접수함의 글이 지시로 쓰이지 않도록 Claude에는 도구를 주지 않고 노션 쓰기는 스크립트만 한다

## 결과

- 좋은 점: 새 피드백이 들어온 다음 날 아침이면 같은 기준의 요약이 접수함 맨 위에 생긴다
- 좋은 점: 서버, 앱, Worker 변경과 새 비용이 없다
- 나쁜 점: 도넛 개인 구독과 setup-token(1년)에 기대고, 끊기면 요약도 멈춘다
- 나쁜 점: 설명란이라 서식이 없고 이전 요약은 덮어써져 남지 않는다
- 나쁜 점: 상태 변경만 있는 날은 요약이 바뀌지 않는다
- 나쁜 점: 공개 저장소라 Actions 로그로 내용을 검토할 수 없다

## 다시 논의해야 할 조건

- setup-token을 쓸 사람이 없거나 구독 한도로 실행이 자주 실패할 때
- 새 피드백마다 바로 반응하는 자동화가 필요해질 때
- 요약에 서식이나 지난 요약 보관이 필요해질 때
- Claude가 도구로 다른 데이터를 조회해야 할 때
