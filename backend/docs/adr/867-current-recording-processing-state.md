# current 응답의 status로 최신 본인 녹음 한 건의 RECORDING·PAUSED·PROCESSING만 제공하고 처리 종료 결과는 204로 제외한다.

## 상태

Proposed

## 관련 Issue

- #867 [BE] 최신 녹음의 문서 생성 중 상태 조회

## 한 줄 요약

current 응답의 status로 최신 본인 녹음 한 건의 RECORDING·PAUSED·PROCESSING만 제공하고 처리 종료 결과는 204로 제외한다.

## 왜 이 결정이 필요했나

홈에서 활성 녹음만 보이고 종료 이후 처리 중 녹음은 보이지 않는 공백을 current API 확장으로 메운다.

홈에서 녹음을 종료하면 current가 204로 바뀌어 전사·문서 생성이 진행 중이어도 진행 상태를 확인할 수 없다.

결정 동인:

- 기존 current API 활용
- 사용자가 정한 최신 한 건과 진행 상태만 표시
- DB 녹음 상태 유지
- FE 홈 표시와 새 녹음 시작 분리

## 트레이드 오프

- 별도 processing 목록 API를 추가한다. 처리 대상을 독립적으로 조회할 수 있지만 홈에서 조회를 조합하고 한 건을 선택해야 한다.
- 기존 current 응답을 확장한다. 홈에서 한 건의 녹음과 처리 상태를 받으며 기존 소비자에 대한 상태 해석과 문서 갱신이 필요하다.

## 무엇을 결정했나

current 응답의 status로 최신 본인 녹음 한 건의 RECORDING·PAUSED·PROCESSING만 제공하고 처리 종료 결과는 204로 제외한다.

사용자가 별도 API 대신 current 확장을 선택하고 여러 건·세부 단계·실패 표시를 제외한 최소 수정 계획을 승인했다.

## 결과

- 새 응답 필드·영속 상태 없이 홈은 단건 status로 표시한다.
- 정상 완료와 실패는 current의 204로 통일되어 이 API에서 구분하지 않는다.
- 최신 처리 종료 뒤 과거 녹음은 다시 노출하지 않는다.
- 문서 처리 중에도 새 녹음을 시작할 수 있다.

## 구현 범위

2026-10-20 사용자 요청에 따라 #867·PR #868은 백엔드 current API와 관련 테스트·문서만 포함한다.
홈 표시·주기 조회·독의 상태 해석은 프론트엔드 후속 작업으로 남긴다.

## 다시 논의해야 할 조건

- 홈에서 완료·실패 결과 또는 과거 작업 복원이 필요해질 때
- 여러 녹음이나 팀원 처리 상태를 표시해야 할 때
