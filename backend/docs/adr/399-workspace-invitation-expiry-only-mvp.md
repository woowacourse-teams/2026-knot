# 초대 코드와 링크의 공통 만료와 취소 없는 복수 발급

## 상태

Proposed

## 관련 Issue

- #399 [BE] 취소 없는 복수 초대와 공통 만료

## 한 줄 요약

한 초대의 코드와 링크를 함께 발급하고 생성 24시간 뒤 함께 만료한다. 복수 초대·다수 수락을 허용하며 취소·발급자 관리를 제외한다.

## 왜 이 결정이 필요했나

기존 초대는 공통 24시간 만료와 재발급 무효화를 사용한다. 사용자는 최소 MVP 단순화와 작은 PR 단위를 요청했다.

발급자별 취소와 목록을 도입하면 기존 행의 미확인 발급자 이관과 추가 API가 필요했다. 사용자에게 필요한 코드 입력·링크 공유·다수 수락은 유지해야 한다.

결정 동인:

- 사용자가 확정한 입력·공유 규칙 보존
- MVP 관리 기능 최소화
- 기존 유효·만료·무효 초대 효력 보존

## 트레이드 오프

- 단일 재발급: 관리가 단순하지만 복수 유효 초대 요구와 충돌해 미채택
- 발급자 또는 OWNER 취소: 만료 전 차단이 가능하지만 권한·관리 흐름이 늘어 미채택
- 취소 없는 복수 초대: 다수 공유를 유지하고 관리 기능을 줄이지만 만료 전 개별 차단 불가; 채택
- 수단별 독립 만료: 코드·링크의 유효 기간을 다르게 둘 수 있으나 현재 MVP에는 필요가 없어 공통 만료로 변경

## 무엇을 결정했나

한 초대의 코드와 링크는 기존 `expiresAt` 하나를 사용한다. 생성과 만료가 같고, 정확히 만료 시각부터 둘 다 사용할 수 없다. 다른 초대는 자신의 만료 시각까지 유지한다.

사용자는 취소 없는 MVP를 채택한 뒤 2026-10-03 공통 만료 권고를 수용하고 #443 수정·push를 요청했다. 이 결정은 앞선 독립 만료 결정을 대체한다. 같은 초대를 전달하는 두 수단에 별도 상태를 두지 않아 사용과 구현을 단순화한다.

## 결과

- 신규 코드는 A-Z 6자리, 코드·링크는 생성 시각부터 공통 24시간이며 사용자 지정·연장·복원은 없다
- 비삭제 Workspace 활성 OWNER/MEMBER가 같은 권한으로 발급만 하며 원문은 발급 응답에서만 제공한다. 초대 목록·다시 보기·발급 횟수 제한은 두지 않는다
- legacy expires_at과 invalidated_at의 효력을 보존하고 발급자를 추측하지 않는다
- I01은 공통 만료 회귀와 FK RESTRICT를 검증한다. 독립 만료 컬럼·생성 경로·fallback은 제거한다. 공통 expires_at과 고정24시간 CHECK를 유지하고 단수 UNIQUE·구 API는 후속 전환까지 유지한다
- FE가 발급·미리보기만 사용하므로 기능 플래그 없이 구 재발급·원문 조회 API를 제거한다. 기존 숫자 코드는 만료 전까지 서버에서 인정한다
- Superseded 범위: ADR171의 단일 초대·재발급 무효화 정책. 공통 24시간 만료는 유지한다. ADR229의 HMAC·난수는 유지하고 원문 재조회용 AES-GCM 암호문 저장은 대체한다. 기존 암호문 컬럼과 암호화 key는 #458의 V22 migration과 배포 설정 정리로 제거했다
- Workspace 삭제는 별도 접근 차단이다. 만료 전 개별 취소가 없는 위험을 수용한다

## 다시 논의해야 할 조건

- 실제 유출 대응으로 개별 취소가 필요할 때
- 사용 횟수 제한이나 사용자별 TTL이 필요할 때
