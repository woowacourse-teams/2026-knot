# 서버가 실제 워크스페이스 멤버십에 사용자별 마지막 조회 상태 하나를 저장하고, FE가 화면 진입 성공 후 명시적으로 갱신한다.

## 상태

Proposed

## 관련 Issue

- #265 [BE] 마지막으로 본 워크스페이스 저장 및 조회 구현

## 한 줄 요약

서버가 실제 워크스페이스 멤버십에 사용자별 마지막 조회 상태 하나를 저장하고, FE가 화면 진입 성공 후 명시적으로 갱신한다.

## 왜 이 결정이 필요했나

워크스페이스 목록 정렬만으로는 최근 참여와 최근 사용을 구분할 수 없고, 기기 로컬 상태는 여러 기기에서 일관되지 않다.

FE 로그인 라우팅 계약을 확정하면서 기기 로컬 저장, 목록 첫 항목 추론, 서버 관리 포인터를 비교했고 접근권한 상실과 빈 멤버십의 동작까지 결정했다.

결정 동인:

- 여러 기기에서 같은 마지막 조회 기준을 제공한다.
- 목록 정렬과 자동 진입 선호를 분리한다.
- 현재 멤버십에 속한 워크스페이스만 가리키게 한다.
- 접근권한 상실 시 임의의 대체 워크스페이스를 선택하지 않는다.
- 동시 갱신에서도 사용자별 값은 최대 하나여야 한다.

## 트레이드 오프

- 기기 로컬 저장: 구현은 단순하지만 다른 기기와 브라우저 초기화에서 상태가 일치하지 않는다.
- 목록 첫 항목을 자동 진입 대상으로 사용: 추가 저장은 없지만 최근 참여와 최근 사용을 혼동하고 사용자 의도를 표현하지 못한다.
- Member가 workspace id를 직접 참조: 조회는 단순하지만 멤버십 생명주기와 별도 포인터를 동기화해야 한다.
- WorkspaceMember에 마지막 조회 상태를 저장: 실제 소속과 상태 생명주기를 일치시키고 행 삭제로 함께 정리할 수 있다.

## 무엇을 결정했나

서버가 실제 워크스페이스 멤버십에 사용자별 마지막 조회 상태 하나를 저장하고, FE가 화면 진입 성공 후 명시적으로 갱신한다.

서버 동기화와 멤버십 기반 저장을 결합하면 여러 기기 일관성, 권한 유효성, 삭제 정리를 하나의 모델에서 보장할 수 있고 FE는 명시적 nullable 값만 해석하면 된다.

## 결과

- workspace_members에 마지막 조회 상태와 사용자별 부분 유니크 인덱스를 추가한다.
- 목록 응답에 nullable lastViewedWorkspaceId가 추가되고 별도 PUT API가 필요하다.
- 동시 갱신을 순차 처리하기 위한 잠금과 PostgreSQL 통합 검증이 필요하다.
- 생성·초대 수락은 상태를 바꾸지 않고 FE가 화면 진입 후 PUT을 호출해야 한다.
- 멤버십 삭제 시 포인터 정리가 자동으로 이뤄진다.
- 저장 실패는 화면 진입을 막지 않으며 다음 로그인에서 이전 상태가 보일 수 있다.

## 다시 논의해야 할 조건

- 멤버십과 무관한 개인별 워크스페이스 설정을 함께 저장해야 할 때
- 한 사용자가 여러 기기별로 다른 마지막 조회 상태를 원할 때
- 워크스페이스 삭제·탈퇴 정책이 멤버십 행 보존 방식으로 바뀔 때
