# OWNER가 미리보기 없이 전체 재정리를 승인하고 기존 목록을 유지한 채 백그라운드 준비 후 주제·문서 배정과 직전 복원 정보를 일괄 적용한다.

## 상태

Proposed

## 관련 Issue

- #934 [BE] 큰 주제 재정리 시작 API 구현

## 한 줄 요약

OWNER가 미리보기 없이 전체 재정리를 승인하고 기존 목록을 유지한 채 백그라운드 준비 후 주제·문서 배정과 직전 복원 정보를 일괄 적용한다.

## 왜 이 결정이 필요했나

신규 문서의 큰 주제 배정 기반을 확장해 기존의 세부 폴더 분산을 정리하는 사용자 기능이다.

서로 다른 회의에서 나온 관련 문서들이 한 문서짜리 세부 폴더로 분산되어 찾기 어렵다.

결정 동인:

- 수천 문서 처리 중 탐색 가용성
- 부분 배정 비노출
- 직전 변경 복원과 기존 자료 보존

## 트레이드 오프

- 미리보기와 개별 확인 후 적용: 변경 검토는 가능하지만 검토·승인 단계와 화면이 추가된다.
- OWNER 실행을 전체 승인으로 보고 비공개 준비 후 전체 적용: 검토 단계가 줄지만 직전 변경 복원과 품질 검증이 필요하다.

## 무엇을 결정했나

OWNER가 미리보기 없이 전체 재정리를 승인하고 기존 목록을 유지한 채 백그라운드 준비 후 주제·문서 배정과 직전 복원 정보를 일괄 적용한다.

사용자가 미리보기 없는 전체 적용을 선택했고 긴 작업 중 기존 목록을 사용할 수 있어야 한다.

## 결과

- 진행·취소·실패 복구와 직전 복원 정보를 공통으로 관리해야 한다.
- #913의 기존 문서 미변경 제외 범위를 이번 별도 기능에서 확장하며 신규 문서 생성 흐름을 보존한다.

## 다시 논의해야 할 조건

- 미리보기·수동 이동이 제품 범위에 추가될 때
- 의미 분류 정확도나 처리 시간이 합의 기준을 충족하지 못할 때
