# Discord 회의 명령 운영 기록

확인일: 2026-10-06 (Asia/Seoul). 관련 [Issue #505](https://github.com/woowacourse-teams/2026-Knot/issues/505), [구현 계획](../implement-plan/505-discord-meeting-command.md).

## 사용법

1. Knot 서버의 접근 가능한 텍스트 채널·스레드에서 `/회의 생성`을 실행한다.
2. 기본 정보 폼에서 날짜를 선택하고 시간·구분·대상·장소를 입력한다.
3. 전송 후 나에게만 보이는 `다음 · 안건 작성`으로 주제·결정해야 할 것을 작성한다.
4. 비공개 미리보기에서 확인·수정한 뒤 `공지 확정`을 누른다.
5. 공지 아래 `회의 수정`과 `회의 취소`는 작성자만 사용할 수 있다.

폼의 `전송`은 단계 저장이다. 최종 확정 전에 공개 공지나 역할 알림을 보내지 않는다. Discord는 modal 제출 응답으로 다음 modal을 열 수 없어서 중간 비공개 버튼을 거친다. 기본 전송 버튼 문구는 변경할 수 없다.

| 입력 | 처리 |
| --- | --- |
| 날짜 | 오늘부터 25일 목록에서 필수 선택 |
| 시간 `2030` | `20:30`으로 정리 |
| 시간 `20:30` | 그대로 사용 |
| 연도 | 선택 날짜에 자동 포함 |
| 기존 회의 수정 | 원래 날짜·시간을 채워서 열기 |

날짜 목록은 한국 시간 오늘부터 25일이다. 기존 공지의 날짜가 목록 밖이면 마지막 항목 대신 포함한다. 시간만 직접 입력하며 연도·월·일을 타이핑하지 않는다. 잘못된 시각·과거 일시는 원인을 안내하고 수정할 수 있다. 입력 도중 자동 서식 변경은 없고 제출 후 정리된다.

구분은 `정규 / 긴급 / 백엔드 / 프론트엔드`, 알림 대상은 `FE / BE / Everyone`이다. 두 값은 독립적이다. 장소 200자, 주제 150자, 결정 사항 1,000자까지다. 링크는 표시하며 봇이 열지 않는다.

## 서버와 실행 설정

| 설정 | 실제 값 |
| --- | --- |
| 허용 서버 | `1536954284447633448` |
| 공지 채널 | `회의-일정`, `1557003334567596173` |
| FE 역할 | `1536963487627087977` |
| BE 역할 | `1536957281483366450` |
| 설치 SDK | discord.py 2.7.1, Python 3.14 |
| launchagent | `gui/501/com.knot.discord-assistant` |
| 저장 파일 | `~/Library/Application Support/KnotDiscordAssistant/meetings.sqlite3` |

채널은 사용자 승인으로 공통 카테고리에 새로 만들었다. 명령은 허용 guild에 한 개 등록한다. 다른 guild command가 발견되면 덮어쓰기를 막고 오류를 기록한다. 역할·채널 ID는 인증 비밀값이 아니다. 실제 Discord·Notion 토큰은 Keychain에 있으며 이 문서에 넣지 않는다.

봇과 요청자 모두 실행·공지 채널의 조회·전송 권한을 확인한다. 봇은 embed 권한이 필요하다. Everyone은 양쪽 전체 멘션 권한이 필요하고 FE·BE는 실제 역할과 멘션 가능 여부를 확인한다. 선택 대상만 멘션하고 사용자 입력의 임의 멘션은 이스케이프한다.

수정은 같은 공지를 갱신하며 취소는 빨간색 `취소됨`과 버튼 제거로 처리한다. 공지는 삭제하지 않는다. 수정·취소는 역할을 다시 알리지 않는다. 새 회의 게시 이외에 AI·Notion 호출, 자동 리마인더, 반복 일정, 캘린더 연동은 없다.

재시작 명령:

```sh
launchctl kickstart -k gui/501/com.knot.discord-assistant
```

로그는 `~/Library/Logs/KnotDiscordAssistant/stderr.log`다. `meeting.commands.synced`, `meeting.views.restored`, `meeting.published`, `meeting.changed`, `meeting.failed`의 stage·failure_code로 실패 위치를 구분한다. Mac 전원·로그인·네트워크가 필요하며 꺼진 동안 버튼을 처리하지 않는다.

## 상태 저장과 복구

미확정 초안은 메모리에만 남고 시작 후 10분간 유효하다. 재시작 시 미확정 초안은 다시 작성한다. 게시된 회의는 작성자·메시지·채널 ID, 회의 내용, revision, 취소 상태와 처리 중 변경을 SQLite에 보관한다. 파일 권한은 0600이다. 저장소 밖에 위치하고 도구 디렉터리에서도 SQLite·journal을 ignore한다.

초안 lock은 동시 확정을 제한한다. 단일 봇 프로세스의 저장소 lock·revision은 오래된 수정과 동시 변경을 막는다. 기존 공지를 바꾸기 전에 pending 내용을 저장하고 성공 후 확정한다. 응답이 유실되면 실제 메시지를 기존·예정 embed와 비교해 복구한다. 둘 다 아니면 자동 변경을 멈춘다.

신규 Discord 게시와 로컬 저장은 하나의 트랜잭션이 아니다. 신규 전송 결과가 불분명할 때 자동 재전송하지 않는다. 게시 후 저장 실패는 공지와 저장소 오류를 구분해 안내한다. SDK 내부 재시도까지 포함한 전역 exactly-once 또는 여러 호스트 동시 운영을 보장하지 않는다. 취소 내역 자동 삭제 정책은 없다.

## 검증 기록

사용자는 실제 BE 멘션 공지 한 번과 수정·재시작·취소 검증을 승인했다. Discord 클라이언트에서 폼과 비공개 미리보기, 공지 게시, 재시작 후 수정 폼 기본값, 같은 메시지 수정, 취소 표시·버튼 제거를 확인했다.

시험 공지: [[동작 확인용] 회의 예약](https://discord.com/channels/1536954284447633448/1557003334567596173/1557005609704890460). 실제 회의가 아니라는 문구가 들어 있고 최종 상태는 취소됨이다. 저장된 revision은 2다. BE 역할만 최초 게시에 멘션했다. FE·Everyone 실제 수신, 다른 계정에서 버튼 거부, 권한 제거와 실제 네트워크 장애는 호스트에서 검사하지 않았다.

실제 검증에서 발견해 고친 오류:

- 비공개 미리보기를 일반 Message API로 편집하여 NotFound가 발생했다. 저장된 InteractionMessage 응답 편집으로 바꾸고 실제 수정·취소 완료 화면에서 정상 동작을 확인했다.
- 저장된 ISO 날짜를 폼 형식으로 검사하여 재시작 복원이 실패했다. 저장소 round-trip 테스트가 수정 전 실패했고 JSON 복원과 폼 파싱을 구분한 뒤 통과했다. 재시작 로그에서 View 한 개 복원도 관측했다.

전체 봇 검사 명령:

```sh
uv run --python 3.14 \
  --with 'discord.py>=2.6,<3' --with 'httpx2[http2]' \
  --with 'mcp>=1.12,<2' --with 'keyring>=25,<27' \
  --with 'pydantic-settings>=2.8,<3' --with 'structlog>=25,<26' \
  --with pytest --with anyio \
  python -m pytest tools/discord-knot-assistant -q
```

최종 날짜 선택·시간 입력 구현 후 로컬 결과: **81 passed, 15 warnings**. 입력·날짜·시각 오류, 날짜 선택과 시간 정리, 목록 밖 기존 날짜 보존, SDK 폼 구성, 값 보존, 저장 복원, 동시 전송, 비공개 응답 편집, 작성자·revision 제한, pending 복구를 검사했다. 경고는 설치된 discord.py의 `escape_markdown` 내부 정규식 positional count 사용에 대한 Python DeprecationWarning이다. LSP는 사용자가 설치를 거절해 실행하지 않았다. 모의 네트워크 테스트는 실제 서버 알림 수신을 증명하지 않는다.

UI 변경 후 실제 Discord 기본 정보 폼에서 10-08 선택과 `2030` 입력을 제출하여 `2026-10-08 20:30` 표시와 `다음 · 안건 작성` 버튼을 관측했다. 두 번째 안건 폼, 비공개 미리보기, 기본 정보 수정 시 원래 날짜·정리된 `20:30`·구분·대상·장소가 채워지는 것도 확인했다. 이 추가 확인은 비공개 초안으로 진행했다.
