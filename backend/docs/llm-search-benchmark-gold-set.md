# Knot LLM 문서 검색 벤치마크 골드셋

## 1. 문서 상태

- 상태: 초안
- 목적: Raw Context, Local RAG, MCP 검색 방식의 답변 품질과 응답 시간을 동일 질문으로 비교
- 기준 Workspace: `자바님의 워크스페이스`
- 기준 프로젝트: `knot`
- 기준일: 2026-09-01
- 정답 문서 식별 기준: 문서 제목이 아니라 Notion page ID와 URL

이 문서는 실제 Notion MCP로 검색하고 원문을 fetch한 페이지를 기준으로 작성했다. 모든 비교군은 아래 질문을 동일한 순서와 동일한 NIM 설정으로 실행한다.

## 2. 공통 평가 기준

한 질문의 성공은 다음 조건을 모두 만족하는 경우다.

- 답변이 정답 문서의 의미를 왜곡하지 않는다.
- 문서에서 확인할 수 없는 사실을 추가하지 않는다.
- 관련 문서가 질문과 직접 관련 있다.
- 관련 문서는 필요할 때만 최대 3개까지 제공한다.
- 문서가 충돌하면 하나를 임의로 최종 정답으로 선택하지 않는다.
- 답이 없으면 찾지 못했다고 명시한다.
- 후속 질문은 같은 세션의 이전 대화 맥락을 사용한다.

Notion MCP가 반환한 `verification.state`는 `unverified`이므로, 최종 벤치마크 확정 전에 사람이 각 정답 문서와 한 번 대조한다.

| model | 사용한 NIM 모델명 |
| cold_or_warm | `cold` 또는 `warm` |
| ttft_ms | 첫 응답 토큰까지의 시간 |
| total_ms | 전체 응답 완료 시간 |
| answer | 실제 AI 답변 |
| source_ids | AI가 제시한 Notion page ID 목록 |
| answer_correct | 사람이 원문과 대조한 결과 |
| sources_relevant | 모든 출처가 직접 관련 있는지 여부 |
| conflict_handled | 충돌을 적절히 처리했는지 여부 |
| abstained_correctly | 무응답·명확화가 필요한 경우 적절히 멈췄는지 여부 |
| notes | 누락, 환각, 잘못된 문서 선택 등 |

## 7. 우선 실행 순서

1. `G-001`~`G-009`로 사실·근거·날짜·후속 질문·범위 구분을 검증한다.
2. `G-010`~`G-012`로 충돌·없는 정보·넓은 질문에 대한 안전한 응답을 검증한다.
3. `G-013`으로 관련 문서 추천 품질을 검증한다.
4. 각 질문을 `raw` → `rag` → `mcp-replay` → `mcp-live` 순서로 동일 실행한다.
5. 정확성 기준을 통과한 방식끼리 TTFT와 전체 응답 시간을 비교한다.
