# #505 Discord 회의 생성·수정·취소 구현 계획

상태: 구현 완료, Discord 실제 생성·재시작·수정·취소 확인. 회귀 검사 결과는 운영 기록 참조.
확인일: 2026-10-06, 한국 시간.
대상: [Issue #505](https://github.com/woowacourse-teams/2026-Knot/issues/505).
담당자: 사용자 확인 흑곰. 이슈 라벨: `흑곰`, `BE`, `Feature`.

사용자가 구현을 승인했고, 이후 공지 채널 고정과 게시 후 수정·취소를 추가했다. 이 문서는 최초 계획을 현재 구현 범위로 갱신한 것이다. 커밋·push·PR은 별도 요청 범위다.

## 1. 범위와 브랜치

인자 없는 `/회의 생성` 하나로 미리 정의된 폼을 연다. 명령은 허용 Knot 서버의 접근 가능한 텍스트 채널·스레드에서 실행할 수 있고, 공지는 항상 `#회의-일정`에 게시한다.

| 항목 | 실제 입력 방식 | 필수 여부 |
| --- | --- | --- |
| 일시 | 날짜 선택 + `HHmm` 또는 `HH:mm` 시간 직접 입력, 한국 시간 | 필수 |
| 구분 | `정규 / 긴급 / 백엔드 / 프론트엔드` 선택 | 필수 |
| 알림 대상 | `FE / BE / Everyone` 선택 | 필수 |
| 장소 | 회의실 이름·음성 채널 이름·회의 링크 등 자유 입력 | 필수 |
| 주제 | 최대 150자 | 필수 |
| 결정해야 할 것 | 여러 줄, 최대 1,000자 | 필수 |

구분과 알림 대상은 독립된 선택값이다. 구분에서 백엔드를 골랐다고 알림 대상을 자동으로 BE로 바꾸지 않는다. 장소 링크는 표시만 하고 서버에서 조회하지 않는다.

Discord modal 최대 5개 컴포넌트 제한에 맞춰 기본 정보 5개, 안건 2개로 나눴다. 첫 폼 제출 후 비공개 `다음 · 안건 작성` 버튼으로 다음 폼을 연다. modal 제출 응답으로 새 modal을 직접 열 수 없는 제약을 따른다. 기본 전송 버튼의 문구도 변경할 수 없다.

최종 사용자 결정은 날짜 선택과 시간 직접 입력이다. 날짜 목록은 오늘부터 25일이다. 기존 공지 수정 시 원래 날짜가 목록 밖이면 마지막 항목 대신 포함하여 유지한다. 시간은 `2030` 또는 `20:30`으로 입력하고 제출 후 `20:30`으로 정리한다. 날짜 목록에는 실제 연도를 포함한 값이 저장되어 연말의 다음 해 선택은 그대로 유지한다. 과거 일시를 다음 해로 자동 넘기지 않는다.

브랜치는 `be/feature/#505`다. 처음 `origin/develop`의 `77e2d927`에서 만들었고, 사용자 요청으로 추가 머지 `962ee782`를 fetch 후 fast-forward 반영했다. 기존 FE 변경과 회의 기능 파일의 충돌은 없었다. 기반 챗봇 [PR #451](https://github.com/woowacourse-teams/2026-Knot/pull/451)은 이미 develop에 병합되어 있다.

이 작업은 개발 생산성 도구다. 제품 V2 진입 문서를 확인했으며 Spring API, frontend, 제품 DB와 Notion 쓰기 권한을 변경하지 않는다. 예약은 회의 일정을 공지·관리한다는 의미다. 시작 전 자동 리마인더, 반복 일정, 캘린더 연동, AI 안건 생성은 구현 범위에 없다.

## 2. 사용자 흐름

```text
/회의 생성
  → 기본 정보 폼: 날짜 선택·시간 입력·구분·대상·장소
  → 작성자 전용 다음 · 안건 작성 버튼
  → 안건 폼: 주제·결정 사항
  → 작성자 전용 미리보기: 전체 내용과 #회의-일정 표시
  → 확정: 입력·역할·작성자와 봇의 권한 재확인
  → #회의-일정에 공지 한 개와 선택 대상 멘션
  → 공개 공지 아래 회의 수정 / 회의 취소 버튼
```

작성자만 공개 버튼을 사용할 수 있다. 수정은 기존 기본 정보와 안건을 채운 폼에서 시작하고 비공개 미리보기의 `수정 확정`으로 같은 공지 메시지를 갱신한다. 안건만 바꾸려면 수정 미리보기의 `안건 수정`을 사용한다. 수정 초안을 취소하면 기존 공지는 유지한다.

회의 취소는 비공개 확인 단계를 거쳐 기존 공지를 빨간색 `취소됨`으로 바꾸고 공개 버튼을 제거한다. 공지 메시지를 삭제하지 않는다. 수정·취소 때 새 공지를 만들거나 역할을 다시 알리지 않는다.

| 상황 | 구현한 처리 |
| --- | --- |
| 빈 입력·공백·잘못된 날짜·과거 일시 | 해당 항목 안내, 값 보존 후 수정 경로 제공 |
| DM·다른 서버·지원하지 않는 채널 | 회의 명령 실행 거부 |
| 요청자·봇의 실행 채널 또는 공지 채널 권한 부족 | 채널과 권한 원인 안내, 게시 차단 |
| FE·BE 역할 누락·멘션 권한 부족 | 해당 대상만 차단, Everyone 대체 없음 |
| 다른 작성자의 버튼 | 거부, 회의 상태 변경 없음 |
| 중복·동시 확정 | 초안 AnyIO lock과 상태 검사로 최초 전송만 시도 |
| 오래된 수정 미리보기 | 저장된 회의 revision이 달라지면 거부 |
| 미확정 초안 만료 | 생성 후 10분, 다시 명령 실행 안내 |
| 봇 재시작 | 미확정 초안은 복원하지 않음. 게시된 회의 버튼과 내용은 복원 |
| 신규 전송 결과 불명 | 자동 재전송 없음, 공지 채널 확인 안내 |
| 기존 공지 변경 결과 불명 | pending 변경 저장. 실제 메시지와 비교해서 다음 버튼 또는 재시작 때 상태 복원 |

Everyone은 요청자와 봇 모두의 공지 채널 전체 멘션 권한을 요구한다. FE·BE는 역할의 mentionable 설정 또는 양쪽 멘션 권한을 확인한다. 선택 역할만 `allowed_mentions`로 허용하며 입력 안의 임의 멘션은 이스케이프한다.

## 3. 코드와 책임

| 파일·클래스 | 책임 |
| --- | --- |
| `meeting_models.py` | 동결된 Pydantic 입력 모델, 구분·대상 enum, 한국 시간 파싱, 미래 일시 검사, 단계별 오류 |
| `meeting_session.py` | 작성자·실행 채널·원시 입력·수정 세대·10분 초안 상태와 AnyIO lock |
| `meeting_time.py` | 날짜 선택 목록 25개, 기존 날짜 보존, 시간 입력 정리 |
| `meeting_forms.py` | 기본 정보 Label/TextInput/Select 5개, 안건 TextInput 2개, 검증과 값 보존 |
| `meeting_access.py` | 실행·공지 채널 권한, 대상 역할, allowed_mentions, 입력 이스케이프, 공지 embed |
| `meeting_views.py` | 비공개 단계 버튼, 미리보기, 신규 게시 또는 수정 확정, 만료·취소 |
| `meeting_commands.py` | 하나의 guild slash group/subcommand, 서버 범위 검사와 sync |
| `meeting_repository.py` | 게시된 회의·작성자·revision·pending 변경을 SQLite에 저장 |
| `meeting_published.py` | 작성자 전용 공개 수정·취소, 취소 확인, 같은 메시지 변경, pending 복구와 persistent View 복원 |
| `assistant.py` | 기존 Client에 CommandTree와 회의 저장소 연결, setup_hook에서 등록·복원 |
| `settings.py`, `.env.example` | 실제 서버의 FE·BE 역할과 회의 채널 ID 설정 |
| `bot.py` | Modal Select를 위한 `discord.py>=2.6,<3` 의존성 |

설치된 SDK는 실제 Mac에서 discord.py 2.7.1로 관측했다. guild command 목록은 등록 전에 비어 있었다. sync는 허용 guild에서 한 번 수행하고, 기존의 다른 명령이 발견되면 덮어쓰기를 차단하여 로그를 남긴다. 명령 등록·회의 저장소 복원 실패가 기존 문서 질의 Client 실행을 막지 않게 분리했다.

## 4. 저장과 외부 전송 경계

미확정 초안은 메모리에만 남긴다. 게시 후 수정·취소 요구가 추가되어 확정된 회의는 `~/Library/Application Support/KnotDiscordAssistant/meetings.sqlite3`에 보관한다. 파일 권한은 0600이고 Git 저장소 밖이다. 도구 디렉터리의 SQLite 파일·journal도 ignore한다.

SQLite에는 공지 message ID, 채널 ID, 작성자 ID·표시 이름, 회의 내용, revision, 취소 여부와 처리 중인 변경을 저장한다. 토큰·Notion 문맥·Discord interaction 전체 payload를 넣지 않는다. 회의 내용은 공지한 내용을 그대로 보관한다.

단일 Mac 봇 프로세스에서 동작한다. 초안 잠금은 신규 중복 게시를 막고, 저장소 잠금과 revision은 수정·취소 충돌을 막는다. 변경할 내용을 먼저 pending으로 저장한 뒤 기존 Discord 메시지를 수정하고 성공 시 확정한다. 복구는 실제 메시지 embed와 저장된 기존·예정 내용의 일치를 확인한다. 어느 쪽과도 다르면 자동 변경을 멈춘다.

신규 메시지 전송과 SQLite 저장은 하나의 원자적 트랜잭션이 아니다. Discord가 수락한 뒤 응답이 유실되면 ID를 모를 수 있으므로 공지를 자동 재전송하지 않는다. 전송은 성공했지만 로컬 기록 저장에 실패하면 공지 상태와 저장소 오류를 따로 안내한다. SDK 내부 전송 재시도까지 포함한 전역 exactly-once를 보장하지 않는다.

Mac 전원·로그인·네트워크 의존성은 기존과 같다. 게시된 버튼은 재시작 후 복원하지만 Mac이 꺼져 있을 때는 처리되지 않는다. 취소 내역도 저장 파일에 남으며 자동 삭제 정책은 없다.

## 5. 구현과 검증

구현 후 사용자에게 BE 멘션 공지 1회와 생성·수정·재시작·취소 검증을 승인받았다. 실제 Discord 클라이언트를 조작하여 입력 폼, 미리보기, 게시된 버튼과 동일 메시지 갱신을 확인했다. 시험 공지는 마지막에 취소됨으로 남겼다.

초기 실제 검증에서 두 오류를 발견해 수정했다.

1. 비공개 미리보기를 일반 Message 편집 API로 정리하여 NotFound가 발생했다. InteractionMessage의 응답 편집 경로를 사용하도록 수정했고 수정·취소 완료 화면에서 정상 동작을 관측했다.
2. 저장된 ISO 날짜를 입력 폼 형식으로만 검사해 재시작 복원이 실패했다. 저장소 round-trip 회귀 테스트가 수정 전에 실패했고, JSON 복원 모드와 폼 파싱을 구분한 뒤 통과했다. 실제 재시작 로그에서 게시된 View 한 개 복원과 기본값 수정 폼을 확인했다.

`test_meeting.py`는 입력 오류, 공백, 과거 일시, SDK 폼 구성, 저장·재시작, 비공개 응답 편집, 동시 확정 한 번, 작성자·stale revision 제한, pending 변경 복구를 검사한다. Discord 네트워크 경계 fixture 결과는 실제 서버 알림 수신을 증명하지 않는다. 기존 봇 테스트도 함께 실행했다.

```sh
uv run --python 3.14 \
  --with 'discord.py>=2.6,<3' --with 'httpx2[http2]' \
  --with 'mcp>=1.12,<2' --with 'keyring>=25,<27' \
  --with 'pydantic-settings>=2.8,<3' --with 'structlog>=25,<26' \
  --with pytest --with anyio \
  python -m pytest tools/discord-knot-assistant -q
```

현재 검사 수와 실제 서버 결과는 [회의 명령 운영 기록](../operations/discord-meeting-command.md)에 기록한다. Python LSP는 사용자가 설치를 거절한 상태여서 실행하지 않았다. 확인하지 않은 FE·Everyone 실제 전달, 다른 계정으로 버튼 거부, 실제 네트워크 장애·권한 제거 상황은 통과했다고 표현하지 않는다.

## 6. 완료 기준과 인계

- 하나의 인자 없는 명령, 필수 입력 6개, 구분 4개·대상 3개, 값 보존·수정·미리보기 제공.
- 공지는 고정된 #회의-일정에 게시하고 선택 대상만 멘션.
- 예약자만 공개 수정·취소, 같은 공지 갱신, 취소됨 표시, 재시작 후 버튼 복원.
- 입력·권한·역할·중복·만료·저장소·전송 단계 오류를 구분.
- 생성·수정·취소는 AI와 Notion에 의존하지 않음.
- 운영 문서에 구현, 단위 검사, installed SDK, 실제 호스트 관측의 범위를 구분.

이슈 기획의 최초 게시 계약 ID는 `bf83a54031eac457`, 장소 개정 계약 ID는 `3f809ba63eb5df93`다. 이후 사용자가 공지 채널 고정·구분 추가·게시 후 수정·취소를 직접 요청하여 이 문서와 구현 범위를 확장했다. 최초 Issue의 계획 검증 Pass를 구현 검증 결과로 사용하지 않는다.
