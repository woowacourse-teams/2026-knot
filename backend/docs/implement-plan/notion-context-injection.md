# 백엔드 구현 계획의 Notion 근거 탐색 설정

## 1. 범위와 브랜치

- 상태: 문서·스킬 설정 반영. 실제 기능 계획에서의 에이전트 실행은 별도 관측 대상.
- 확인일: 2026-10-08. 현재 브랜치: `be/feature/#521`.
- 대상: 로컬 원문 캐시 Git 제외, 저장소 공통 관련 근거 탐색·선별·계획서 출처 기록.
- 현재 사용자의 #521 코드·테스트·ADR 변경은 이 작업의 대상이 아니다.

| 근거 | 이번 작업에 적용한 사실 | 판정 |
|---|---|---|
| 사용자 요청 | 원문 파일 전체를 올리지 않고 관련 문서를 찾아 계획에 반영해야 함 | 확정 |
| `.gitignore`, `git ls-files backend/docs/notion` | 원문 캐시는 추적되지 않았고 기존 ignore가 없었음 | 작업 전 관측 |
| `harness/sync_notion_docs.py` | 수집 범위로 원문·속성을 복제하며 의미를 선별하는 도구는 아님 | 현재 구현 관측 |

## 2. 구현할 흐름

```text
작업 요청·Issue → 현재 V2 기준·관련 ADR·코드 확인
→ 관련 API/도메인/기획의 파일 목록 검색
→ 선택한 본문·필요한 DB 속성·의존 근거 읽기
→ 수정 시각·누락·현재 적용 여부와 실제 구현 대조
→ 계획서에 필요한 규칙·출처·미확정 사항 기록
```

전체 캐시·서식 JSON은 기본 문맥에 넣지 않는다. 캐시가 없거나 필요한 근거가 불완전하면
읽은 근거와 읽지 못한 부분을 구분하며, 설계에 영향을 주는 미확정만 남긴다.

## 3. 나올 코드와 메서드 초안

이번 설정에는 새 제품 클래스·메서드가 필요하지 않다.

| 파일 | 현재 반영한 책임 |
|---|---|
| `.gitignore` | `/backend/docs/notion/` Git 제외, 로컬 파일 보존 |
| `backend/docs/notion-context.md` | 작업별 탐색 범위, 검색 방식, 추출 필드, freshness와 실패 처리 |
| 저장소 내 `backend/docs/notion-context.md`의 근거 표 | 도구에 관계없이 계획 전 근거 선별 절차와 출처 기록 |
| 백엔드 AGENTS·API 스킬·현재 V2 기준 | 전체 사본 대신 탐색 기준을 진입점으로 연결 |
| 기존 동기화 절차·예약 작업 | 원문 캐시 수집과 검토한 문서 갱신을 구분 |

## 4. 저장 기반과 주의할 점

DB·migration 변경은 없다. 원문 캐시는 계속 로컬에서 갱신할 수 있으나 Git에는 포함되지 않는다.
다른 개발자의 checkout에는 캐시가 없을 수 있으므로 출처는 원문 URL 또는 추적되는 문서로 남긴다.
일반 `rg`는 ignored 파일을 건너뛰므로 지정된 캐시 경로에 한해 `--no-ignore`를 사용한다.
전체 원문 430개를 정제 완료했다고 주장하지 않는다. 확정 규칙의 주제별 정제는 실제 내용을 읽고 수행해야 한다.

## 5. TDD와 검증 순서

제품 동작 변경이 없어 제품 테스트 추가·실행은 필요하지 않다. 이번 설정은 실제 Git·검색 동작으로 확인한다.

| 검증 | 기대 결과 | 확인 상태 |
|---|---|---|
| `git ls-files backend/docs/notion` | 추적 파일 없음 | 확인 |
| `git check-ignore -v backend/docs/notion/manifest.json` | 루트 .gitignore 규칙 적용 | 확인 |
| 캐시 경로에 `rg --no-ignore`로 재시도/Job 검색 | 관련 API 후보를 찾을 수 있음 | 확인: API 후보 15개; 전부 관련 있다고 판단한 것은 아님 |
| 선택된 후보 본문·manifest 읽기 | 검색 발견과 실제 읽기를 구분 가능 | 확인 |
| 대상 파일 `git diff --check` | 공백 오류 없음 | 확인 |
| 다음 실제 기능 계획 실행 | 관련 근거를 읽고 적용 사실·출처·판정을 기록 | 아직 관측하지 않음 |

## 6. 완료 기준과 다음 작업

ignore·탐색 기준·저장소 내 API 스킬 연결을 반영했다. 개인 스킬·특정 대화·개인 디렉터리에 의존하지 않는다. 이 설정은 다음 계획에서 에이전트가 따라야 하는
근거 수집 절차이며, 모델의 실행 결과를 강제하는 검색 엔진이나 자동 정제 시스템은 아니다.
다음 기능 계획에서 실제로 선택한 근거와 적용 규칙이 적절한지 확인한다.
계획에 필요한 사실은 선별하고, 주제별 기준 문서가 필요한 경우 원문·Issue·ADR·코드 대조 후 갱신한다.
