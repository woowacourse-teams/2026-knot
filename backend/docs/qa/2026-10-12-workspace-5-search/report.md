# Dev Workspace 5: 가상 문서 30개 및 실제 탐색 검증

2026-10-12 실제 Dev RDS에 테스트 문서 30개를 추가했다. 로컬 DB나 임시 메모리 데이터가 아니다. Dev 웹에서 Workspace 5를 선택해 사용할 수 있다.

## 데이터

- Workspace 5, 기존 소유 Member 2. Workspace 및 멤버십을 변경하지 않았다.
- 문서 ID 31~60, 모두 ARCHIVED. 제목 접두어는 `[탐색 테스트 20261012]`.
- 주제 10개, 주제별 회의 3개. 녹음 시점은 2026-09-01~2026-10-10.
- ENDED 녹음 30개, 전사 30개, 전사 구간 30개, 생성 Batch 30개, Batch 주제 30개, SUCCEEDED Job 60개(분류 30개·생성 30개), 문서 확인 30개를 연결했다.
- 문서와 전사는 가상 기록임을 본문에 표시했다. 실제 녹음 오디오 파일은 만들지 않았다.
- 첫 삽입을 ROLLBACK으로 검증한 후 실제 COMMIT했다. 첫 트랜잭션에서 기존 47개 행의 전체 행 해시를 비교해 보존을 확인했다. 전사 구간 추가도 기존 구간의 보존을 검사했다. 기존 행 UPDATE/DELETE는 수행하지 않았다.
- ROLLBACK 검증의 identity 소비로 문서 ID는 1이 아닌 31부터 시작한다.

생성한 모든 ID는 [manifest.json](manifest.json), 전사 구간 ID는 [segments.json](segments.json), 날짜·주제·사실 원본은 [fixtures.json](fixtures.json)에 있다. 원격 보관 위치는 `/var/lib/knot-dev-search-fixtures/ws5-20261012`이다. 인증 비밀은 이 파일들에 포함하지 않았다.

## 실제 환경과 관찰

- 공개 API `https://dev-api.knoted.kr`를 HTTPS로 호출했다.
- 실제 실행 프로세스 설정: `LLM_MODEL=qwen3.8-27b`, `LLM_BASE_URL=https://llm-api.knoted.kr`, `LLM_PROVIDER=lm-studio`, 탐색 agent 및 worker 활성.
- 기존 Workspace 5 소유자로 인증해 CSRF 발급 후 요청했다. 단기 테스트 인증 토큰은 프로세스 메모리에서만 사용했다.
- 실제 API가 모델의 탐색·답변 생성을 수행했다. 제어된 생성 adapter 결과가 아니다.
- 첫 질문 7개와 후속 질문 1개: 총 8개 중 7개 COMPLETED, 1개 FAILED. 정상 완료 시간 13.71~30.17초.
- 정상 답변은 아래 예상 사실과 일치했다. 반환된 카드의 문서 ID는 모두 31~60에 포함됐으며 최대 3개였다. 메시지 조회에서 저장된 답변 본문과 SSE 본문이 일치했다.
- 정상 7개 응답에서 `excluded_documents.count=0`을 확인했다.

## 발견된 실패

근거 없는 질문은 conversation 7 / question 15 / answer 16에서 `ANSWER_GENERATION_FAILED`로 종료됐다. 서버 로그는 `SearchToolException`을 기록했지만 상세 오류 코드를 기록하지 않아 이 관찰만으로 정확한 예외 원인은 특정하지 못했다.

동일 question 15를 실제 재시도 API로 다시 실행했다. 기존 answer 16을 재사용하는 accepted 이벤트가 왔고, 빈 evidence 이후 다시 FAILED로 종료됐다. USER 메시지가 추가되지 않았고 전체 테스트 메시지는 16개로 유지됐다. 따라서 근거 없음의 정상 완료는 이번 실제 환경에서 검증 실패이며 재시도에서도 재현됐다. 성공 사례 수에 포함하지 않았다. 이번 작업에서 서버 코드나 배포 설정은 수정하지 않았다.

## 조회 검증

- 문서 목록: 15개씩 2페이지를 조회해 중복 없이 30개, 주제 10개를 확인했다.
- 문서 31 상세 및 연결 전사 조회: HTTP 200, ARCHIVED 및 전사 구간 확인.
- 완료 답변 2 재연결: HTTP 200, snapshot → evidence → completed, 기존 본문 복구.
- DB 최종 조회: 30개 모두 ARCHIVED이며 SUCCEEDED 생성 Job에 연결됐고 전사 구간도 존재한다.

전체 질문·응답·SSE·메시지 조회는 [results.json](results.json), 목록·상세·전사·재연결·재시도는 [supplemental.json](supplemental.json)에 기록했다. 이번 30개는 짧고 정답이 명확한 가상 문서다. 긴 문서 이어 읽기, 수천 개 문서의 성능, 실제 회의 기록의 답변 품질을 통과했다고 해석하지 않는다.
